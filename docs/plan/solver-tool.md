# 推算工具（AI 第二级）

状态：2026-11-14 按评估顺序进入“AI 第二级”。同日用户确认第 7 节四项均按建议，第十六轮（执行器与命令行）已完成本地验收并按用户授权提交推送，见第 8 节执行记录；第十七轮（MCP 服务器）已完成本地验收并按用户授权提交推送，尚未在桌面客户端中接入，见第 9 节执行记录。更新：2026-11-14。

## 1. 目标

让 AI 自己多轮调用本地求解器：写出推算请求，拿到结果（机位、时刻、偏差、试看链接），放宽或改动条件再算，最后把机位链接交给用户。使用者可以是能运行命令的编码助手，也可以是接入工具协议的桌面客户端。

分工沿用[机位推算](reverse-planning.md#5-ai-辅助)的规则：

- AI 只负责把需求写成推算请求、解释结果；星历、地形与视线都由求解器计算。
- 坐标目标标为“未核实”；AI 不能把几何对齐说成“一定能拍到”。

## 2. 现状

- 已有：推算请求 v2 的公开格式、schema、`#solve=` 链接，以及结果的 Markdown 表格（AI 第一级）。
- 搜索流程写在界面里：读地形、求解、筛选、视线、合并结果、计数，都在 `src/ui/solve/Composition.tsx` 的 `useComposition` 中（`searchLine`、`searchWindow`、`searchPair`、`searchGrounds`），依赖 React 状态。
- 求解器本身是纯函数，测试一直在 Node 中运行。
- 地形读取在 `src/io/elevation.ts`：Mapterhorn 瓦片是 512 px 的 WebP（terrarium 编码），用浏览器的 `createImageBitmap` 和画布解码。Node 22 不能直接解码 WebP。
- 光污染分块在仓库的 `public/light-pollution/` 下，可直接读文件。

## 3. 方案

### 3.1 共享的搜索执行器（任何形式都需要）

- 把四种搜索从界面移到一个不依赖 React 的执行器（暂名 `src/domain/solve/composition-run.ts`）。
  - 输入：面板条件或推算请求 v2，以及镜头、离地高度、折射、时区、拍摄时刻。
  - 注入的读取函数：地形瓦片、光污染、进度、取消。
  - 输出：结果条目与各项计数，即现在的 `Run` 中与界面无关的部分。
- 界面改为调用它，保证应用和工具给出同样的结果。Worker 分派仍在界面一侧。

### 3.2 形式

| 方案 | 好处 | 代价 |
| --- | --- | --- |
| 命令行（仓库中 `npm run solve -- 请求文件`） | 任何能运行命令的 AI 助手都能用；不引入协议依赖 | 需要在仓库里运行；输出为文本（JSON 或 Markdown） |
| MCP 服务器（stdio） | 桌面客户端可直接接入，工具带结构化参数和说明 | 新增 `@modelcontextprotocol/sdk`（MIT，1.32.2；会带进 express、hono 等十多个依赖）；用户需要在客户端里配置 |

建议本轮做执行器和命令行。MCP 放到下一轮，作为命令行之上的薄封装，提供三个工具：推算、校验请求、说明格式。

### 3.3 Node 中的 WebP 解码

| 候选 | 说明 |
| --- | --- |
| `@jsquash/webp` 1.5.0 | Apache-2.0，WebAssembly，不需本地编译，只依赖 `wasm-feature-detect` |
| `sharp` 0.35.5 | Apache-2.0，本身绑定 libvips 预编译二进制（libvips 为 LGPL-3.0），体积大，按平台下载 |

- 建议用 `@jsquash/webp`，只用于命令行，不进网页包。
- 准入前要验证：对固定瓦片，解码出的高程与浏览器解码逐像素一致（WebP 无损编码时应完全相同）。

### 3.4 输入与缺省

- 读推算请求 v2（文件或标准输入），v1 照常转换。
- 命令行没有“打开者的当前计划”，请求中省略的项按固定缺省补上，并在输出里逐项列出：
  - 镜头：24 mm、全画幅、3:2 横幅；
  - 离地高度 1.6 m，标准折射；
  - 日期：请求时区（没有时为 UTC）的今天；时区：请求给的，没有时为 UTC。
- 也可以用 `--shot` 传一个机位链接或 JSON，作为“当前计划”。

### 3.5 输出

- 缺省输出 JSON，包含：
  - 规范化后的请求与用到的缺省；
  - 可解性；
  - 每个结果：日期、时段、机位、方向与距离、偏差、天空、月亮，以及打开该试看机位的 `#shot=` 链接；
  - 被挡、筛掉、其他目标不在位置等计数；
  - 读了多少地形瓦片、数据来源与限制。
- `--format markdown` 输出与面板“复制结果”相同的表格。
- 链接的站点默认为公开站点，可用 `--site` 改。

### 3.6 网络与署名

- 命令行在本机读取 Mapterhorn 瓦片，与网页用同一公开服务。
  - 单次搜索的瓦片数沿用现有上限与降级（不超过 40 块）；
  - 同一进程内缓存，按顺序或少量并行请求；
  - 输出写明数据来源与署名。
- 不调用天气、潮汐等其他服务。

## 9. 第十七轮：MCP 服务器

2026-11-14 用户说“继续”，按第 4 节进入第十七轮。

### 范围

- **共用步骤**：命令行的“读请求、补缺省、搜索、组装结果”抽到 `scripts/lib/solve-run.mjs`，命令行与 MCP 服务器都调用它。命令行的输出与退出码不变。
- **服务器**：`scripts/mcp.mjs`（`npm run mcp`），stdio 传输，每行一条 JSON-RPC 2.0 消息。
  - 支持 `initialize`、`ping`、`tools/list`、`tools/call`，以及 `notifications/initialized`、`notifications/cancelled`。
  - 客户端给出 `progressToken` 时，用 `notifications/progress` 汇报搜索阶段。
  - 标准输出只写协议消息，其余写标准错误。
- **工具**：

  | 工具 | 输入 | 输出 |
  | --- | --- | --- |
  | `solve` 推算 | 推算请求（对象、JSON 文本或 `#solve=` 链接），可选当前机位 `shot` 与最多返回的结果数 `maxResults`（缺省 20） | 与命令行 JSON 相同的结果，同时作为结构化内容与文本返回；超出部分只计数 |
  | `validate_request` 校验请求 | 同上，不含 `maxResults` | 规范化后的请求与其链接、请求描述、用到的缺省、能否搜索；无效时列出带字段路径的问题。不联网 |
  | `describe_format` 说明格式 | `solve`（缺省）或 `shot`，可选要 JSON Schema | `public/` 下生成的格式说明或 schema |

  - 请求无效、不能搜索、搜索失败时，以工具错误（`isError`）返回原因，便于 AI 改了再试；未知工具与参数类型错误按协议错误返回。
  - 服务器附一段使用说明：数值由求解器计算；坐标目标未经核实；结果是几何对齐，不代表一定能拍到；把 `#shot=` 链接交给用户确认。
- **不加依赖**：协议部分自己实现（约 200 行），不引入 `@modelcontextprotocol/sdk`。只用到工具这一部分，自己实现比 SDK 连带的十多个依赖更轻；协议版本按客户端请求在 `2025-11-25`、`2025-06-18`、`2025-03-26`、`2024-11-05` 中协商。
- **接入配置**：
  - 仓库根目录加 `.mcp.json`，Claude Code 在本仓库中会提示是否启用；
  - README 写明其他客户端（如 Claude Desktop）的配置写法，需要用绝对路径。

  - 客户端给出 `progressToken` 时，搜索阶段至多每 300 ms 发一次进度通知；
  - 收到取消通知即中止搜索，不再回应；标准输入关闭时中止所有搜索，其余调用照常回应。
