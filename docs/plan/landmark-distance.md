# 地标远景与建筑覆盖

后续状态（2026-11-08）：本文保留扩距时的悬空画面及未通过项；地形覆盖不足导致的间隙已在[地表校准](landmark-ground-calibration.md)中修正并另行验收，不覆盖原始证据。

2026-11-07，按用户要求推进：晴空塔加载范围从五公里独立扩为约 50 km，普通建筑继续使用周边五公里窗口；全场建筑（含地标）三角面上限由 120,000 调为 300,000，普通轮廓入选点由 80,000 调为 160,000。原始响应、缓存、候选扫描和瓦片数量上限保持有界。本轮不增加其他地标、纹理或整城远程建筑，不默认提交推送。

当前模型已固定来源、几何和近似注册；远处直接读取已注册同源模型与其锚点 DEM，不要求该目标出现在机位附近 MVT 窗口。普通窗口与地标足迹相交时仍验证三处粗分部的源 ID、位置和高度，再替换；模型失败或对应不明时分别表达近处回退与远处未加载。远景不假设存在普通粗体块。地标与普通建筑继续共享 WGS84 方向、曲率、主深度、雾及遮挡，50 km 是读取上限，不是可见性保证。

数值验证覆盖距离边界与地球背面拒绝，五公里边缘分部、远距独立加载、失败与取消、共享预算，以及 10/30/50 km 的坐标与曲率。沿用相同真实 MVT 输入对比旧/新预算，记录入选数量、三角面和内存。实际 Chrome 检查原机位覆盖、10/30 km 远距、长焦/拖动、关闭重开、失败和手机视口，性能与画面结果分开表达。尚未执行的项保持待验。

## 实现与数值验证

本轮已完成加载范围、预算、状态及数值检查，并核对远景可见性；**30/50 km 的塔脚与远处地表衔接未通过，仍需校准**。没有据此宣称实景可见性或远景地面接触精度。原模型、压缩文件与来源注册不变，没有为远景另造几何、修改高度或改变大气参数。

三维弦长使用 WGS84 地面坐标，不混入离地高度，约 50 km 内与地表弧长的差异远小于当前注册精度。原方法仅取水平 ENU 分量，在地球背面附近也可能得到接近零的距离，现使用全部三分量拒绝。模型仍通过锚点 ENU 转为真实观察者 ENU，保留曲率，不投放到平面地图上。

锚点距机位不超过 5 km + 100 m 时，在整块源瓦片上先验证三处 ID/位置/高度，再做普通五公里候选过滤；因此部分粗分部跨过窗口边缘时仍可确认，替换只移除实际入选的对应分部。更远时没有需替换的普通塔身，直接复用已注册静态模型，不额外获取塔址 MVT。地标锚点仍单独读取同源 DEM；普通区域读取失败仍使整体建筑图层失败，尚未拆成两个独立发布通道。

`npm test` **243 项通过**，`npm run build -- --base=/Tamatamatori/` 通过，保留已有大包提示。新增四项检查覆盖：

- 10/30/49 km 的范围、曲率及普通瓦片未被扩大，约 50 km 的范围边界与地球背面拒绝。
- 新旧预算在同样地标成本下的覆盖增加，以及点数/三角面的双重上限。
- 五公里外无目标粗分部或远处瓦片时仍能加载，失败提示、取消及范围外不读取模型。
- 五公里边缘只有部分分部进入候选时仍正确确认、失败保留粗体块、对应变更拒绝替换。

既有 ENU/ECEF 对照扩至约 30/50 km，密集首瓦片用例扩到超过 16 万源轮廓点。原索引绘制、GL 状态和模型资源校验检查继续通过。资源、源码、测试及构建签名见[verification.json](landmark-distance-evidence/verification.json)。

## 同输入预算对比

东京普通分部约增至 8.25 倍；源候选仍为 57,451，覆盖不完整，不能把入选数量当作实地建筑栋数。2–5 km 普通远景分部从 317 增至 2,027。新旧东京均读 32 瓦片、原响应 17,639,273 B，上海均读 29 瓦片、3,224,561 B；请求清单完全相同，提高预算没有增加这一固定机位的初次源流量。新机位仍需要其周边数据。

最坏普通非索引几何为 300,000 × 72 B，约 20.6 MiB；加入当前地标时先预留其面数和索引存储，东京实际约 17.03 MiB。地标仍最多 80,000 顶点，不能把普通源轮廓点数称作 GPU 顶点总数。原始响应、解码中间对象、DEM 和 GPU 副本另有内存占用；此数不是浏览器总内存上界。

可用[回放脚本](../../scripts/check-building-budget.mjs)重放同一源缓存。需事先有报告中 SHA-256 对应的瓦片，默认从忽略的 `.cache/building-assessment/storage/` 和 `.cache/building-distance/` 读取，不自动批量下载。脚本只在 `.cache/landmark-distance/` 生成旧预算模块，不修改应用源码。最初采用 data URL 导入时 Node 无法解析裸包名，未得到结果；改为忽略目录中的本地模块后完成对照。以上表格采用已完成的重复回放，不将初始化失败计入性能数据。

## 尚未解决的画面问题

三十/五十公里长焦图中，地标下部与远处地表之间能看到分离，原因尚未确定，需分别排查 DEM 取景覆盖、网格/深度、地平线雾混合与地标基座注册。数值投影一致不能代替地面接触画面验收；本轮没有为了掩盖间隙调低模型、延长塔脚或添加虚构地面，也没有套 geoid 常数。

因此本轮可确认更远的地标加载与绘制、更多普通建筑及边界/失败状态；不能保证完整远地形遮挡或远处塔脚真实接地。**下一小步优先处理远景地表衔接和遮挡范围**，再考虑远景 LOD 或新地标。原模型社区来源、约 6.48 m 轮廓注册残差、对称朝向歧义、不透明材质等限制继续以[首步记录](skytree-landmark.md)为准。不默认提交推送。
