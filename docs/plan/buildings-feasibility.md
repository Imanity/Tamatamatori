# 建筑与地标预览可行性评估

评估日期：2026-11-07。本文保留进入实施前的资料、渲染路径与四处瓦片抽样评估；当时未实现建筑渲染。后续原型及当前 CPU/GPU 验收状态见[建筑首步](buildings.md)。精细地标的最新数据源、数量、容量预算与塔址样本见[精模专项评估](landmark-models-feasibility.md)，该专项仍未接入应用。

## 结论

可以支持普通建筑，建议以当前 OpenFreeMap 的建筑轮廓和渲染高度形成体块、城市天际线及近似遮挡。重要地标可另外接入有许可、已核对位置和尺度的精细模型；它是普通建筑的补充路径。两者均有沿用当前 React、MapLibre 和 GitHub Pages 的实现空间。

全球选点不等于建筑资料完整。普通建筑的高度、屋顶与分部信息不统一，不能承诺全球实景还原或精确的楼顶日月对齐。下一步优先做有限范围的建筑投影与遮挡验证，不先引入第二套地球引擎、后端或全球模型库。

四处抽样均只有 `render_height`、`render_min_height`、`colour`、`hide_3d` 这些建筑属性，未见原始层数、原始高度来源、屋顶形状或名称。标准生成路径按原始高度优先、其次楼层乘 3.66 m、再缺省 5 m 生成渲染高度，并取整；这是上游生成逻辑参考，尚未核对所抽样版本的确切构建提交。不能由瓦片中“有高度”推断“有实测高度”，也不能把所有 5 m 要素直接判定为缺省。

晴空塔抽样点所在多边形中包含高度 634 m 且 `hide_3d=true` 的外轮廓，以及其他底部高度不同的分部。忽略 `hide_3d` 后整体拉伸会产生多余实体；遵守它仍不保证完整还原塔身。名称或地图 POI 可以支持搜索，却不自带可用的三维几何。这说明知名地标同样需要具体核查，不能只读取周边最高的高度值就宣称已经支持。

本次验证证明现有源可返回建筑几何与属性。浏览器渲染、远处城市覆盖、真实楼高、地标外形和运行性能仍未验收。四个城市瓦片不能代表全球质量。

## 与当前预览的兼容性

以下为结合仓库代码的工程判断，具体路径待小规模原型验证。

当前预览通过 WGS84 → 局部 ENU 计算地形，使用真实摄影相机与对数片元深度。已安装的 SDK 桥接只覆盖地形，不覆盖建筑。当前 `fill_extrusion` 顶点仍使用 MapLibre 的原投影，片元也没有摄影对数深度，因此不能只往 `terrainStyle` 增加普通 `fill-extrusion` 图层作为完成接入。[现有摄影投影](../architecture/terrain-perspective.md)

可比较两种局部方案：扩展固定 SDK 的建筑顶点、片元及深度绘制桥接；或解码有限范围建筑瓦片，生成网格，通过公开 custom layer 绘制。前者可复用瓦片管理，需继续核验源码/ESM 签名、安装幂等和原地图不受影响；后者更便于精细地标共用摄影坐标，但要自行处理获取范围、三角化、分部、瓦片边缘及缓存。评估阶段不预先定案或新增通用框架。

无论采用哪条路径，都需要先解决：

- **落地与高度**：建筑相对高度与地面高程分开。简单体块可用既有 DEM 的局部基座高度；坡地须避免悬空、钻地和倾斜屋顶，不能让每个屋顶顶点都随地面起伏。带绝对高程的城市模型先核实垂直基准，不能直接与当前未知统一基准的 DEM 相加，也不能套固定 geoid 常数。
- **统一遮挡**：建筑写入与 DEM 一致的主深度，绘制先于日月、星空、银河、深空与天气天空合成。建筑既能被山体挡住，也能挡住天体。标注和搜索可见性更新到当前场景，区分建筑未加载与实际未遮挡；不能继续将所有结果称为“DEM 未遮挡”。雨雪前景效果按当前定义保留。
- **长焦与请求范围**：机位所在瓦片不足以保证拍到远处地标。应按机位、方向、视场与有限距离请求，验证低俯仰角下的 SDK 瓦片覆盖，避免方向一变建筑消失。原生 z14 不会因放大到更高级别自动增加屋顶细节。
- **资源与稳定性**：按需加载、取消旧机位请求、缓存有界、失败单独反馈；方向和焦距修改不重建地形。不把当前空瓦片解释为实地没有建筑。密集城区和手机的三角面、CPU 解码、显存及帧耗时需实测后设上限，不能提前承诺全球实时帧率。

高度误差对构图很敏感：仅用平面小角度举例，1 km 外的楼顶差 10 m，方向就相差约 `atan(10/1000) = 0.57°`。因此体块预览适合选方向和估计天际线；长焦楼顶日月合影仍需地标几何、基座高程和实际机位的独立核验。该例是误差敏感性计算，不是某数据源的实测误差。

## 地标补充路径

地标可按单目标处理，避免一次承担全球精细建筑流式加载的成本。候选包括晴空塔、东京塔等辨识度高的对象，当前只作核查候选，没有确认某一份模型的可再分发许可或几何质量。

1. 优先核查政府开放模型，例如覆盖区域内的 PLATEAU；其他模型逐份检查作者、再分发许可、下载条款、纹理和衍生处理要求。网页上能浏览或免费下载不等于能纳入仓库发布。
2. 固定原始资料、文件哈希、采集年份、地理锚点、朝向、单位、基座和总高；将精细模型离线转换/简化为适合静态分发的 glTF/GLB 等格式。姿态和深度必须接入现有摄影坐标，普通地图模型示例仅作为加载参考。
3. 精细模型替代同一建筑的粗体块，使用经核验的对象关联或空间覆盖排除重复建筑。塔架、空洞和尖顶需要真实网格或明确的简化轮廓，不能以整块长方体冒充。
4. 按场景需要加载少量模型，保留来源、模型年份与“简化模型”说明。只支持一个地标时，周边建筑遮挡仍可能不完整，须与地标本身是否成功绘制分开表达。

夜间灯光、窗户材质、营业照明时刻与反射无法由普通建筑轮廓自动获得。首步只随当前环境调整材质明暗；具体灯光和照片级外观另行评估。

## 建议的下一小步及准入验收

先完成一个有限城市范围的普通建筑原型，验证当前最关键的摄影投影与遮挡；通过后再单独补一个精细地标。当前建议不是已经获选的数据精度承诺或实现结果。

首步提供默认关闭的“建筑”图层，右侧对应设置/读数呈现来源、数据版本和体块近似。暂不增加全球建筑搜索、纹理城市、真实建筑照明或账户/后端。先固定东京一处城市场景，并以陆家嘴作独立数据对照；具体加载距离和资源上限由原型测量确定。

完成标准：

1. 合成建筑验证相对高度、分部底高、孔洞和 `hide_3d`；瓦片边缘、多多边形、重复分部、缺字段与异常高度有明确处理。
2. 独立 CPU ENU 对照、SDK/自定义层数值与实际 GPU 分开记录。用 24/85/200/1000 mm 验证地面接缝、近裁剪和远近遮挡，误差阈值根据固定场景建立，不把渲染数值一致宣称为实景精度。
3. Chrome 验证建筑挡日月/恒星/深空、山体挡建筑、拖动和调焦连续性、夜间/月光/天气叠加；关闭恢复、换机位迟到响应、加载失败与无数据均可区分。
4. 桌面和手机记录峰值瓦片/三角面/内存、请求数量与稳定拖动帧耗时；复验普通地图、既有地形深度和天空。没有实际 GPU 证据时不能标为渲染通过。
5. 原型通过后，再选一份许可和定位均已核验的地标模型，单独验证长焦轮廓、尺度、DEM 基座和与粗体块替换关系。

该次评估仅修改文档并保存接口抽样，没有变更应用、增加依赖、提交或推送。PLATEAU、Overture 和 Google 在评估时只核对公开文档，未进行对应模型下载、账号/账单开通或 GPU 接入。
