# 远山 DEM 细节与采样一致性

更新：2026-11-04。状态：安装复现、数值回归、构建与 Chrome 主路径通过；实景精度边界继续保留。

## 本轮范围

保留 Mapterhorn Terrarium 512 像素、最高 z12 数据。处理远山在长焦下反而变粗、与固定 z12 采样不同的问题；不更换引擎或数据源，不处理地球曲率、真实水位、网络恢复或其他天体。

当前 SDK 6.16.0 的 `setSourceTileLodParams` 只传给 DEM 下载覆盖，`TerrainTileManager` 生成绘制网格时未传入同一计算函数。先作版本固定、签名校验、可重复安装的最小兼容修正，再验证公开 LOD 参数及其资源代价。禁止直接修改运行时私有字段；不把预取高精度瓦片当作网格已经使用该精度。

## 验收

- 真实 SDK CPU 覆盖：确认参考点所在的绘制网格及对应 DEM 层级，覆盖广角、长焦、横竖幅和水平观察；保留原有相机眼点与瓦片越界检查。
- 固定参考点独立采样：少量读取 z9—z12，确定高程变化是否对应具体数据层级，而非星历或投影偏移。
- 真实 Chrome：与既有山中湖机位及同一参考点对照，记录加载完成后的采样值、画面、不同镜头与恢复路径；检查日月遮挡仍有效。
- 资源：检查固定场景的瓦片数量、原生级别上限及浏览器加载，不能无限请求远方最高精度瓦片。
- 数学一致性和实景精度分别判断，DEM 垂直基准、源数据和曲率差异继续保留。

前置发现与截图见[相机校准](camera-calibration.md)，实现及升级规则见[远山细节设计](../architecture/terrain-detail.md)。

## 已确认的原因与数值回归

默认网格策略在同一山中湖参考点上，200/1000 mm 会选择粗层级，旧 Chrome 查询值为 3728.85 m。逐级同源采样已确认该值对应 z9；此前另一个 3755.02 m 值对应 z10。不能把这种层级差异当成天文偏移来补偿。

修正后下载和网格都使用同一屏幕细节函数，最高网格 z14、最高 DEM z12，图像仍为 512 像素。网格单元约 8 CSS px 的目标随视场、距离和取景框尺寸变化；不全局强制最高细节。视觉 tileSize 128 用于限制 RTT 颜色纹理开销，不改变图像格式和来源精度。

当前 85 项自动检查通过，新增 5 项：SDK ESM/源代码兼容修正存在、屏幕策略单调性和上限、实际网格管理器覆盖、逐级采样缓存、镜头/画幅复用回调。真实 SDK CPU 覆盖 5 焦距 × 2 画幅 × 3 俯仰，共 30 组；最大 117 个网格和 42 个理想 DEM 瓦片，后者不含加载父瓦片、阴影源和缓存。受测试的长焦参考点使用 z12 数据，网格不超过 z14，原相机眼点与越界回归继续通过。这是固定样本资源检查，不是全球硬性内存或请求上限。

Windows、Node.js 24.17.0 执行 `npm.cmd ci`，重新安装 94 个包并自动应用兼容修正；第二次运行脚本后两个修改文件的 SHA-256 保持一致。全新安装后再次执行全部 85 项测试和 `npm.cmd run build` 均通过，保留原有 MapLibre 包体提示。该记录为本地检查，未把尚未运行的远端 CI 标为通过。

## 保留边界与下一步

DEM 分辨率与垂直基准、公布参考点坐标舍入、山脊前后遮挡和地球曲率仍未解决；本轮不宣称实拍触山时刻或米级地理精度。广角、小取景框、远处地形可按屏幕需求降级，不能把任意机位都标成 z12。网络中断恢复及性能压力测试继续保留原待办。

下一小步建议单独比较地球曲率模型与当前平面模型，再决定采用的渲染路径；不把球面参考标记直接当作地形已经完成曲率修正。
