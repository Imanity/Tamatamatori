# 晴空塔无纹理单体首步

2026-11-07。本轮按用户“不需要纹理”要求，只接入晴空塔一处精细地标，已完成本地数值、GL 替身和实际 Chrome 验收。未增加其他地标、纹理、玻璃透光、夜景灯光或后端；未提交推送。

本文保留首步的五公里/12 万面历史结果；当前范围与预算已由后续[地标远景](landmark-distance.md)更新为约 50 km/30 万面，新增远距画面的地表接触问题单独记录，不能沿用本文近距离验收作为通过依据。

## 使用与范围

开启左侧“建筑”，机位位于晴空塔五公里以内时自动尝试加载。先用源瓦片、三处分部 ID、位置及高度共同确认替换关系，模型校验与地面高程读取成功后才替换这三处粗分部，保留邻楼。失败或对应关系不明时保留源体块，右栏显示未应用并提供独立重试。关闭建筑同时停绘地标，恢复当前 DEM 遮挡。

地标与普通建筑共用 120,000 面上限。当前精模占 88,581 面，普通建筑可用预算减至 31,419 面，密集城市会比只有粗体块时更稀疏，继续提示覆盖不完整。普通体块数只计普通源分部，三角面和网格字节含地标。加载、替换、失败及新机位仍清空旧遮挡，纯转向、时间和焦距改变只更新 uniform。交互见[设计](../design/buildings.md)，数据流与 GL 生命周期见[架构](../architecture/buildings.md)。

## 来源与转换

用户完成 Sketchfab 登录后，通过正式下载入口取得 [Tokyo Skytree, Japan](https://sketchfab.com/3d-models/tokyo-skytree-japan-b4d347b8703f45f48ea8d5fe45d454b9)，作者 [Noah / smiN5214](https://sketchfab.com/smiN5214)，CC BY 4.0。选择正式 GLB 1k 档，实际 18,497,376 B。未读取私有预览资源或绕过下载入口。作者页面没有说明更上游的制作资料，其来源未独立认证，不能当作测绘模型。

网站公共元数据曾标注 676,132 面，**下载文件实际解码为六个网格、285,887 面、166,513 顶点**，本轮以取得文件为准，两者口径差异保留，不用页面计数估算最终资源。两种源材质中玻璃带 alpha；本轮全部转为不透明共享材质，透空来自实际几何，不从纹理透明度重建钢构。

| 项目 | 结果 |
| --- | --- |
| 输入 SHA-256 | `007cd38f40f114dc2f2d6c2b8b00c216a95fa6401dbfb15b3946b1c8ca6bb150` |
| 压缩衍生文件 | 1,236,544 B，约 **1.18 MiB** |
| 解压后 CPU/GPU 几何 | 2,636,828 B，约 2.51 MiB（含 32 B 头） |
| 顶点 / 三角面 | 65,576 / 88,581 |
| 压缩文件 SHA-256 | `4ee6a8d802db2ccf0538add4ff7f3b54e21237e4cd36267e7a487852305848cd` |
| 去除内容 | 图片、UV、切线及源材质，不保留源夜灯或玻璃效果 |
| 运行时 | TTLM 1 / gzip，float32 ENU 位置与法线、uint32 索引；无 glTF 运行时依赖 |

六个网格节点共享同一作者场景变换，差异在校验阈值内；去掉共同放置、平移和约 1.62° 倾斜，恢复局部 Y 向上框架。以原始局部 Y 范围约 −0.032724 至 634.210144、上部圆形截面中心 XZ=(2.0669,7.54065) 归一化，转换为右手 ENU。总高按官方[634 m 说明](https://www.tokyo-skytree.jp/about/spec/structure/)统一，不能称源模型各处尺寸都已实测定标。

减面使用固定 @gltf-transform/core 4.5.0 与 meshoptimizer 1.3.0。初步比较 0.02/0.05/0.1/0.2 m 的工具误差参数；采用 0.1 m、锁边界和法线权重 0.01 后，再按独立覆盖检查决定当前档。工具报告误差不是现场测量误差或所有细节位移的严格上限。索引压实会重写索引，转换时必须按 OLD→NEW remap 同步复制位置与法线，不能把压实索引直接用于原始顶点。

源解析记录见[source-inspection.json](skytree-evidence/source-inspection.json)，完整参数与许可见[发布清单](../../public/landmarks/skytree-v1.json)。About 与第三方许可文件集中保留作者、CC BY、加工说明及衍生模型/清单下载。

## 注册及精度边界

锚点由当前 OpenFreeMap / OSM 窄塔尖分部中心确定：纬度 **35.71004508243534**、经度 **139.81071889400482**。替换的三个源 ID 为 3623514152（350/290 m）、2882691482（450/410 m）、3623514142（634/0 m）；隐藏总轮廓 2882691472 继续遵守 hide_3d，不用于实体填充。未来分部变化时须重新确认，不能仅按高度删除周边楼房。

最初尝试拟合 OSM 隐藏总轮廓，但该轮廓接近圆形，得到约 10.82 m 残差且无法确定朝向，因此未采用其旋转结果。随后只参考已下载 PLATEAU 墨田区 LOD2.1 的水平切片：在本地基座上方 30/100/200 m 取截面，排除半径 65 m 外的附属区域，按固定锚点/尺度每 0.25° 扫描旋转。选择 ENU 平面逆时针 **10.25°**，对称轮廓 RMS 约 **6.48 m**，仍存在约 120° 对称歧义和模型形状差异。固定切片与候选见[注册记录](skytree-evidence/section-registration.json)。这是近似朝向注册；不是把 LOD2 当作精细塔架，也不是独立实景校准。

源样本 SHA-256 为 `eea0aea8452f4d9dd4e0c287433f85d2e92557c5b13375f5814dcd3c3cc24746`，URL 与属性见[前轮塔址抽样](landmark-assessment-evidence/plateau-targets.json)。PLATEAU 的高度参考与当前 DEM 基准仍未统一；切片只比较相对水平形状，运行时地面直接沿用同源 DEM，不使用其绝对 Z 或测高字段替换 DEM，不套 geoid 常数。

## 数值、GL 替身与构建

`npm test` **239 项通过**。新增五组检查覆盖：实际资产解析与坏头/截断/非有限/越界拒绝，压缩及已解压响应哈希校验、缓存和取消，局部 ENU 与独立 ECEF 矩阵对照，三分部替换/邻楼保留/失败回退/预算，实际图层的索引与普通数组绘制、VAO 归属及资源清理。此前全部建筑与天文检查保持通过。

首次全量检查有一项 About 下载总数仍期待旧值（238/239）；更新为包含两份地标下载，并检查署名及独立下载入口后，239/239 通过。首次坏文件测试误用了 Node Buffer.slice 的共享存储，已改为独立副本；解析函数也使用明确的 Uint8Array 副本，避免偏移视图问题。两者均为本地检查阶段发现，不作为通过结果隐藏。

`npm run build -- --base=/Tamatamatori/` 通过，保留现有的大分块体积提示。正式 `dist` 通过显式子路径 preview 服务验证，GLB 工具不进入运行时包，公开资源复制路径与下载链接均匹配。重复转换的 gzip SHA-256 与验收时 dist 完全一致，见[资源签名](skytree-evidence/verification.json)。

独立 CPU 使用原始 285,887 面与实际发布网格，六方向（0/60/120/180/240/300°）做正交三角形并集覆盖，分辨率约 0.317 m/px：

- 交并比 **99.528%—99.598%**；覆盖像元到另一网格的最近距离不超过 0.951 m，包含栅格化误差。
- 下部高度 20–140 m、横向绝对距离 15–35 m 的侧边带，透空比例变化 **0.50—0.77 个百分点**。这只比较源网格与减面结果，不证明实地钢构都正确。
- 同一行左右界限最多差 4.121 m：薄水平杆件纵向变化不足一像素时，同一行会跳到后面的边界。初步行边界门槛因此未通过，后改用二维最近覆盖距离，同时保留行差诊断，不能把它解释成实际三维位移。

[覆盖数值](skytree-evidence/cpu-coverage.json)、[行差初查](skytree-evidence/cpu-coverage-row-diagnostic.json)、[原始/减面/差异图](skytree-evidence/cpu-coverage.png)。此检查独立于 shader，但不是 GPU 抗锯齿或测绘精度验证。

```sh

```

## 剩余边界与下一小步

本步是一个社区外观精细模型，有源几何与真实 GPU 闭环；没有全局地标覆盖、测绘精度、实测材质、可透玻璃或夜间照明。手机使用 Chrome 视口模拟，未测实体手机；未单独记录 GPU timer 或持续拖拽帧耗时，不把面数上限当作性能基准。

建议下一步先制作晴空塔远景 LOD，沿用当前近景几何作为参考，通过轮廓与透空对比再降低远景面数，把预算还给周边建筑；不直接扩大地标目录。新增地标仍逐份核查上游制作来源、许可、定位、几何、预算与实际画面。
