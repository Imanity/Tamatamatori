# 构图约束搜索

状态：2026-11-13 按用户提出的设计完成评估；同日用户确认第 9 节五项均按建议，第 7 节第一步（推算第十轮）已完成本地验收并按用户授权提交推送，见第 10 节执行记录。更新：2026-11-13。

## 1. 背景

[机位推算](reverse-planning.md)已有三种求法（找时间、找机位、两者都找），第九轮修正后用户试用仍觉费解。用户的例子：近期在 105 mm 竖幅下，让 M31 落在富士山山顶上方，该怎么同时找时间和机位。按现有功能实际查了一遍，问题如下：

- 要先在三种求法中选一种，用户的问题却是“画面里要有什么”。
- 只能让天体中心正好压在目标上，求不出“在山顶上方”或“在左上方”。提前几分钟也不行：M31 斜着落下，会跑到山顶左上方。
- 山顶按地面点处理后，“主体占画面高度”不起作用，只能给最远距离；链接预览里却仍显示主体占比。
- “暗夜”只看太阳。拍深空最要紧的月光需要自己看时间轴。
- 视线时通时挡，同一天被切成多段：90 天共 255 行。

用户提出的设计：

1. **目标列表**：可加入任意多个“目标在画面中的位置”约束。
   - 地面点：经纬度，加上距地表或距海平面的高度。例如距地表 0 m 或海拔 3800 m 的山顶、距地表 630 m 的楼顶。
   - 天体：太阳、月亮等。
   - 每个目标在画面中任意摆放（横、纵都可调），搜索时容忍一定误差。
2. **筛选条件列表**：可加入任意多个条件，例如日期范围、星空可见性。
3. **机位与时间**：可固定机位求时间，固定时间求机位，或都不固定。
4. **搜索按钮**：在上述条件下搜索，结果以列表展示。

## 2. 结论

- **可行**，也比现有三种求法更统一，能表达的更多：
  - 现有三种求法都是它的特例。
  - “在山顶上方”只是两个目标的画面位置不同。
  - “主体占画面多高”可由同一地点的顶部与底部两个点表达。
- **前提有三**，否则通用的条件表单反而比现在难用：
  1. 目标在预览里直接拖放，不只填表；
  2. 实时提示“当前条件能求出什么”；
  3. 常用场景有模板。
- 分三步实施（第 7 节）。只有“两个地面点作主约束”需要新的求解思路，其余能沿用现有求解器。

## 3. 概念模型

### 画面

焦距、传感器、画幅比、横竖幅与离地高度由用户给定，相机保持水平（不旋转）。画面位置写成自左上角起算的比例 (x, y)，取值 0—1。

### 目标（构图约束）

| 种类 | 定义 | 说明 |
| --- | --- | --- |
| 地面点 | 经纬度 + 高度：“距地表 N m”或“海拔 N m” | 海拔与应用的地形高程用同一套数值，基准未核定（见[高程基准核查](elevation-datum-audit.md)）。山顶宜用“距地表 0 m”，第三步加“吸附到附近最高点” |
| 天体 | 太阳、月亮、银心、亮星、深空目标 | 以后可加行星；空间站的可见窗口很窄，另行评估 |

- 每个目标有画面位置与容差。容差按画面高度的百分比，缺省 ±3%，可逐个调整。
- 地面点有离地高度时，可再给“底部（地面）在画面中的位置”。它等价于同一地点的第二个地面点，用来取代现在的“主体占画面高度”。

### 搜索范围

| 变量 | 选项 |
| --- | --- |
| 机位 | 固定（当前机位或地图点选）/ 某点周围 N km / 不限（以目标为中心，最远 N km） |
| 时间 | 固定时刻 / 日期范围（某一天、7 天、30 天、90 天、12 个月或自定） |

“固定机位求时间”“固定时间求机位”“都不固定”是这两项的组合。日期范围不再放进筛选列表，避免同一件事出现两处。

### 筛选条件

| 条件 | 何时计算 |
| --- | --- |
| 天空条件（白天、黄金、蓝调、暮光、暗夜） | 搜索中 |
| 月亮：在地平线下 / 亮面上限 / 与目标的角距下限 | 搜索中 |
| 机位与目标的距离范围 | 搜索中 |
| 星空可见性（太阳、月光与光污染合成的天空亮度上限） | 第二步；光污染要读瓦片，在结果上计算 |
| 排除水面与建筑轮廓内、近处建筑遮挡 | 在结果上检查（沿用[第七轮](reverse-planning.md#第七轮执行记录)） |
| 天气 | 只在预报范围内标注，不作筛选 |

### 搜索与结果

- 显式的“搜索”按钮：显示进度，可以取消。条件改变后，旧结果标为“需要重新搜索”，不自动重算。
- 结果按天合并：每天一行，写出可拍时段、机位范围（地图上的线或点）、各目标的最大偏差、天空与月亮。展开后再看各段。
- 试看、段内滑杆、存为机位、导出日历、复制结果与检查机位沿用现有功能。

## 4. 可解性

5 个可变量：机位经度、机位纬度、时刻、相机方位、相机俯仰。每个“目标在画面某处”用掉 2 个。

| 条件 | 结果形式 | 界面提示 |
| --- | --- | --- |
| 1 个目标 | 任何时间地点都满足，只是对准它 | “再加一个目标，才能确定机位或时间” |
| 2 个目标，机位与时间都不固定 | 每个时刻一处机位：地图上的线 | “结果为机位线” |
| 2 个目标，固定机位 | 多出 1 个条件，只有近似解 | “按容差找时刻” |
| 2 个目标，固定时刻 | 离散的机位点 | “结果为机位点” |
| 3 个及以上目标 | 条件多于变量，只有近似解 | “按容差近似；容差越小结果越少” |
| 只有天体，没有地面点 | 与机位基本无关（月亮视差除外），只求时刻 | “结果与机位无关” |

提示随目标与搜索范围实时更新，并在搜索前给出：缺地面点或缺天体时说明原因，组合尚未支持时写明在哪一步支持。

## 5. 交互设计

右栏推算面板自上而下：模板 → 目标 → 搜索范围 → 筛选 → 可解性提示与“搜索” → 结果。

- **加目标**：
  - 地面点：在地图上点选，或选已接入地标；随后在预览画面中心出现带名称的标记，拖到想要的位置。
  - 天体：从列表选择，同样出现标记，可拖放。
  - 每个标记颜色不同；选中时显示容差框，可用方向键微调。
- **模板**：选模板会填入目标、画面位置与筛选，用户只需改地点与日期。
  - 钻石富士：太阳落在山顶正中。
  - 月亮落在塔尖：塔顶加月亮，塔底定大小。
  - 深空天体在山顶上方：山顶在下三分线，天体在其正上方，月亮在地平线下，暗夜。
- **三种求法退场**：不再有“求解对象”切换，它们由搜索范围表达：
  - 找时间 = 机位固定；
  - 找机位 = 时间为某一天；
  - 两者都找 = 都不固定。
- **预览中的标记**表示“希望在画面中的位置”，与当前画面内容无关。试看后，实际的天体与地面应落在标记上，可直接对照。
- **地图**：画出地面点，以及结果的机位线或机位点，按日期着色；正在试看的结果加粗。

## 6. 技术方案

### 求解策略

按目标组合选一对“主约束”求出候选，其余目标与筛选逐点检查偏差。

| 组合 | 主约束的求法 | 现有基础 |
| --- | --- | --- |
| 1 个地面点 + 1 个天体 | 推广找机位：每分钟由两者的画面位置差，按当前俯仰换算出方位差与高度差，沿偏转后的反方位扫描并二分距离 | `position-alignment.ts`、`aimAt` |
| 多日 | 逐日复用上一行，在后台线程计算 | `range-alignment.ts`、Worker |
| 固定机位 | 第一个目标定朝向，扫描时刻求其余目标的偏差 | 推广 `alignment.ts` |
| 固定时刻 | 主约束一对求离散机位点 | 上述扫描取单一时刻 |
| 只有天体 | 扫描时刻求天体间的相对画面位置；机位取搜索范围中心 | 推广 `alignment.ts` |
| 第三个及以上目标 | 在候选上计算各目标的画面偏差；朝向按全部目标的偏差最小来拟合 | 新增，计算量小 |
| 两个地面点为主约束 | 先由两点的相对位置求出机位线（与时刻无关），再沿线找时刻 | 新求解器，第三步 |

- **遮挡**：每个地面点都要检查从机位出发的视线；天体只要求在地形以上（沿用预览的遮挡口径）。被挡的分钟照第九轮的做法不列出，只计数。
- **性能**：主约束生成候选线的计算量与现在的两者都找相当（晴空塔、月亮 12 个月约 10 s，在后台线程）；其余目标的检查是逐点算术。要联网的检查（光污染、天气、建筑、水面）只在结果上做。
- **结构**：新增 `src/domain/composition.ts`，负责约束模型、可解性分类与策略选择；求解器保持纯函数，可注入地形采样，便于[第 5 节](reverse-planning.md#5-ai-辅助)所说的 MCP 或命令行调用。

### 推算请求 v2

- `tamatamatori.solve` 升为版本 2：
  - `lens`：焦距、传感器、画幅比、横竖幅。画面位置依赖镜头，必须随请求带上。
  - `targets[]`：每项为地面点（坐标或地标、高度与基准）或天体，加上画面位置与容差；地面点可带 `base`（底部的画面位置）。
  - `range`：机位与时间。
  - `filters[]`：筛选条件。
- v1 链接继续可打开，读入时按规则转换：
  - `mark` 加 `camera` → 固定机位，加一个天体目标；
  - `target` 加 `frame` → 一个地面点 + 一个天体，两者画面位置相同；
  - `share` → 地面点的 `base`；
  - `days`、`date`、`sky`、`phase` → 搜索范围与筛选。
- `llms.txt`、格式说明与 schema 仍由 `scripts/formats.mjs` 生成，并校验漂移。

## 7. 分步

每步一个可演示的闭环：

1. **统一界面（取代三种求法）**：
   - 目标最多两个：1 个地面点 + 1 个天体，或 2 个天体。地面点可带底部位置。画面位置任意，带容差。
   - 搜索范围组件；筛选含天空条件、月亮（地平线下 / 亮面上限）、距离。
   - 可解性提示、搜索按钮、按天合并的结果、三个模板、推算请求 v2 与 v1 转换。
   - 验收场景：M31 在富士山山顶正上方、105 mm 竖幅、近期、月亮在地平线下。
2. **更多目标与星空可见性**：
   - 第三个及以上目标按容差检查，例如月亮与 M31 同框再加山顶。
   - 星空可见性筛选：太阳、月光与光污染合成的天空亮度。
3. **两个地面点作主约束**：
   - 叠山、对景、不同地点的前后景。
   - 海拔高度目标，“吸附到附近最高点”。

离地高度上限 100 m 仍另行评估（见[推算实景对照](alignment-validation.md)）。

## 8. 验收方向

- **画面位置**：任一结果试看后，各目标在画面中的位置与设定相差不超过容差。CPU 投影用固定输入检查；真实 GPU 画面在浏览器中量测。
- **退化与转换**：
  - 与现有求解器对照：两目标重合时与第九轮结果一致；固定机位时与找时间一致。
  - v1 请求转换后的结果与原结果一致。
- **可解性提示**：表中每种组合的提示与结果形式都正确，未支持的组合给出说明，不出现空白结果。
- **独立检查**：偏移对齐另用独立的逐分钟采样对照。
- **场景**：
  - M31 在富士山上方：近期日期、机位与月亮条件，与独立星历计算一致。
  - 晴空塔月亮（塔顶加塔底）：与现在两者都找的距离带一致。
- **验证边界**：同前，几何对齐、地形遮挡与实景可见分开表述。

## 10. 第十轮：统一界面（第一步）

### 范围

- **目标**：最多两个，组合为“1 个地面点 + 1 个天体”或“2 个天体”。
  - 地面点：地图点选或已接入地标；高度为“距地表 N m”或“海拔 N m”；可选“底部在画面中的位置”（只取纵坐标）。
  - 天体：太阳、月亮、银心、亮星与深空目标。
  - 每个目标有画面位置 (x, y) 与容差（画面高度的百分比，缺省 ±3%）。
- **搜索范围**：
  - 机位：不限（以地面点为中心，最远 10/20/30 km）/ 当前机位周围 1/3/10 km / 固定为当前机位，并可同时固定当前朝向。
  - 时间：日期范围（起始日加 1、7、30、90 天或 12 个月；固定机位时另有 3 年）/ 固定为当前时刻。
- **求解组合**：
  - 地面点 + 天体，机位不限或周围：机位线；时间固定时为机位点。偏移由两者的画面位置按当前俯仰换算，底部位置按实际投影检查。
  - 地面点 + 天体，机位固定：由地面点定朝向，求天体经过对应方向的时刻。
  - 只有天体：求两个天体的相对画面位置符合的时刻；机位固定或取当前机位（结果与机位基本无关）。
  - 固定机位与朝向：一个天体，求它落到画面位置的时刻（原“找时间”）。
  - 其余组合（两个地面点、三个以上目标、机位与时刻都固定、只有一个目标且朝向不固定）不搜索，并说明原因与支持的步骤。
- **筛选**：天空条件、月亮在地平线下、月亮亮面范围；可加可删。被地形挡住的分钟仍只计数（同第九轮）。
- **可解性提示**与**搜索按钮**：条件改变后旧结果标为“需要重新搜索”，不自动重算；搜索可取消。
- **结果**：按天合并，每天一行（时段、机位距离与方位、最大偏差、天空、月亮），展开后看各段；试看、段内滑杆、剖面、返回推算前、检查机位、存为机位、导出日历、复制请求与结果沿用。
- **预览**：每个目标一个可拖动的标记（天体按真实大小画圈，地面点为十字，底部为短横），方向键微调；改动目标后结果标为过期。
- **模板**：钻石富士、月亮落在塔尖（塔顶 + 塔底）、深空天体在山顶上方（M31，月亮在地平线下，暗夜）。
- **推算请求 v2**：`lens`、`targets`、`camera`、`time`、`timeZone`、`filters`；v1 链接读入后转换。格式说明、schema 与示例重新生成。
- 原“找时间 / 找机位 / 两者都找”切换移除。

### 暂不处理

- 第三个及以上目标、星空可见性、两个地面点、吸附到最高点（第二、三步）。
- 改变两者都找原有的“±20%”主体占比口径：改由底部位置的容差（画面高度的百分比）表达。

### 验收

- **自动检查**：
  - 偏移求解：任一解试看后，地面点与天体投影到各自画面位置，误差在取整范围内；两者位置相同时与第九轮的解一致。
  - 固定机位：与原找时间对同一方向的结果一致。
  - 两个天体：与独立的逐分钟扫描一致。
  - 底部位置：实际投影与设定之差在容差内。
  - 可解性分类覆盖第 4 节每种组合；v1 请求转换后的结果与原结果一致；v2 的读取、报错与往返。
- **交互检查**：加删目标、拖动标记、切换搜索范围、加删筛选、搜索与取消、按天展开、试看与返回、模板、链接载入。
- **浏览器**：M31 在富士山山顶正上方（105 mm 竖幅，近期，月亮在地平线下）；晴空塔月亮（塔顶 + 塔底）；钻石富士模板。

### 第十轮执行记录

2026-11-13 完成本地验收，已按用户授权提交推送。

#### 实现

- **模型与可解性**（`src/domain/composition.ts`）：
  - 目标、搜索范围、筛选与结果条目的类型；`classify` 按第 4 节给出结果形式或原因，并选择求解策略（机位线、固定机位的时刻、两个天体的时刻）。
  - 三个模板；`tryPatch` 统一写出试看字段，两个天体时朝向跟随第一个天体。
- **求解器**：
  - `aimAt`（`alignment.ts`）是 `frameDirection` 的逆，够不到的位置沿对角线向中心收拢。
  - 找机位的求解器接受 `PairFrames`：两个目标的画面位置差按当时的俯仰换算成方位差与高度差，扫描方向与经线收敛修正都按“期望的天体方向”进行；位置相同时与原求解一致。目标可按海拔给高度（`absolute`）。
  - 两者都找的求解器接受底部位置：按试看朝向实际投影目标脚下的地面，在容差内才保留，并记下实际占比。走廊、扇区与高度预筛都按偏移后的方向计算。
  - `scanPair`：两个天体每 10 分钟扫描，接近容差处逐分钟细算，成段输出。
  - `Prefilter`：搜索前在目标处带 0.5° 余量按天空条件与月亮跳过分钟，求解后逐分钟精确检查；钻石富士模板 90 天由 39 秒降为 4 秒。
