# 地形预览验收与相机校准

更新：2026-11-04。状态：Chrome 连接已恢复，三组固定场景完成基础 GPU 画面检查；数值、组件检查通过。真实地理精度、网格防碰撞后的相机高度与网络失败恢复仍有待验项，尚未完成全部校准。

## 本轮范围

检查现有山体与静态水体预览能否稳定表达机位、朝向和镜头构图；本轮不接入天空、天文图层或水面特效。发现能复现的产品问题再修复，不凭数值测试结果推定实景精度。

固定输入保存在 [terrain-scenes.mjs](../../tests/fixtures/terrain-scenes.mjs)，相机验证保存在 [camera-calibration.test.mjs](../../tests/camera-calibration.test.mjs)。运行全部检查使用 `npm test`；只运行地形与相机数值检查使用 `npm run test:terrain`。Windows PowerShell 如禁止运行 npm.ps1，可使用 `npm.cmd`。

浏览器中逐项输入表内经纬度、方位角和俯仰角；高程由实际 DEM 自动获取。**不得把表内合成高程写成真实机位海拔，或用它替换应用的数据加载。** 本轮地图确认 plain 坐标在内陆，并非水岸，已修正场景名称；不在该场景验收湖面。

山峰参考点为日本气象厅公布的富士山剣ヶ峰：35°21′39″N、138°43′39″E、3776 m。[参考来源](https://www.data.jma.go.jp/vois/data/tokyo/314_Fujisan/314_index.html)（查阅：2026-11-04）。这与粗分辨率 DEM 的峰值可能不同；源 DEM 的垂直基准尚未核定，不能据此宣布高程误差已达标。

## 本轮发现与修复

1. 长焦参数更新后，画面可能停留在原构图。实际控制台出现 canonical 瓦片 z26 越界：高虚拟缩放配合 SDK 默认矢量过缩放策略，可能超出其 z25 上限。预览明确设置过缩放参数，使矢量覆盖沿用来源原生层级，同时保留固定眼点所需的相机缩放范围。
2. 俯仰恰为 0° 时仍可能越界。SDK 地形细节层级计算在眼点所在瓦片遇到 0/0，导致覆盖遍历继续细分。渲染角在零点附近保留 0.0000001° 的微小偏移，小于现有校准容差；拍摄计划与界面仍表示请求的 0°。

修复后重新加载并复测上述场景，长焦及水平视角均能更新，无相同控制台错误。两类问题加入真实 SDK CPU 瓦片覆盖回归，不用 SDK 测试替身证明修复。

## 待办与交付判断

- 基础 GPU 加载、镜头响应、布局与覆盖提示已实际检查，不再受浏览器连接阻塞。
- 仍需将山峰参考点投影与实际山脊像素独立对照，并核对 DEM 垂直基准；当前不能承诺米级机位或地形精度。
- 湖岸水面贴附 DEM，长焦岸线有锯齿与交接限制；未验收独立水平水位，也未测量引擎防碰撞后的真实眼点高度。
- 真实浏览器中尚未阻断网络请求来验证失败、重试及快速连续机位切换；现有组件回归通过不能替代该项。

下一小步优先补齐真实网络失败恢复与近地相机位置核对，再决定岸线或相机是否需要调整；时间天空模型继续暂缓。本轮不将全部相机精度校准或 P2 整体标记完成。
