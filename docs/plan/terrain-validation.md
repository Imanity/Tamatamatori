# 地形预览验收与相机校准

更新：2026-11-04。状态：数值和组件验收通过，真实浏览器画面验收受连接故障阻塞，尚未完成本小目标。

## 本轮范围

检查现有山体与静态水体预览能否稳定表达机位、朝向和镜头构图；本轮不接入天空、天文图层或水面特效。发现能复现的产品问题再修复，不凭数值测试结果推定实景精度。

固定输入保存在 [terrain-scenes.mjs](../../tests/fixtures/terrain-scenes.mjs)，相机验证保存在 [camera-calibration.test.mjs](../../tests/camera-calibration.test.mjs)。运行全部检查使用 `npm test`；只运行地形与相机数值检查使用 `npm run test:terrain`。Windows PowerShell 如禁止运行 npm.ps1，可使用 `npm.cmd`。

三个机位均为公开区域附近的候选测试坐标，不代表现场勘察过的安全或可达机位。共同参数：全画幅、35 mm、横向 3:2、离地 1.6 m、UTC `2026-11-04T03:00:00Z`、显示时区 `Asia/Tokyo`。

浏览器中逐项输入表内经纬度、方位角和俯仰角；高程由实际 DEM 自动获取。**不得把表内合成高程写成真实机位海拔，或用它替换应用的数据加载。** 湖岸与平地场景的地表类别也需要在地图和真实渲染中确认。

山峰参考点为日本气象厅公布的富士山剣ヶ峰：35°21′39″N、138°43′39″E、3776 m。[参考来源](https://www.data.jma.go.jp/vois/data/tokyo/314_Fujisan/314_index.html)（查阅：2026-11-04）。这与粗分辨率 DEM 的峰值可能不同；源 DEM 的垂直基准尚未核定，不能据此宣布高程误差已达标。

## 浏览器验收步骤与待办

连接恢复后，在 Chrome 打开本地开发服务，按三组固定场景执行以下步骤。每个场景均记录浏览器版本、预览尺寸、实际机位高程、参数和截图。

1. 等待加载完成，确认有地形、水体及来源署名；控制台和页面均无未处理的加载错误。确认预览容器宽高大于 0。
2. 依次设置 8、35、200、1000 mm，确认视场缩小与目标裁切一致；目标处在当前视场外时，不能为了保留目标而自动移动机位或转向。需要居中比较时，另记一组明确的新朝向。
3. 切换横竖幅，再检查 16:9 和 1:1 裁切。拖动预览和修改朝向，确认地图扇形与参数一致。
4. 调整离地高度至 0.1、1.6、10 m，观察穿地、近裁剪缺口及引擎防碰撞是否改变标称视角。数值测试中的合成平面未覆盖真实网格的近裁剪校正。
5. 拖动分隔条、交换面板，窄屏隐藏预览后再显示；确认画面不拉伸、不归零，不改变机位、时间或镜头参数。
6. 在湖岸检查水体面、地形接缝和坡面异常。水面当前贴附 DEM，只验收边界参考与缺失反馈，不能判定真实水平水位已校准。
7. 连续移动机位，确认旧画面在等待期间隐藏，最终结果对应最新机位；阻断请求后验证失败提示、重试及参数仍可编辑。
