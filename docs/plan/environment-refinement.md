# 环境配置与天气显示优化

## 第一阶段

按用户顺序先完成标注连续性、左栏环境配置与预报模型选择，验证后提交推送。

- 同一机位、拍摄时刻和折射配置下，转动相机时延续已经确认的目标方向遮挡结果，文字位置按当前相机更新。新机位、时刻、图层与失败使保留结果失效。右栏的最新遮挡测量状态单独表达。
- 左侧栏在图层组下增加环境组，包含光污染、天气开关与天气的预报模型子设置，手机沿用同一配置入口。
- Open-Meteo 提供自动匹配、GFS、ICON、ECMWF IFS。模型进入缓存键，切换时取消旧请求，数据来源按所选模型显示。可选能见度缺测单独反馈，核心云雨字段缺测继续暂停效果。

验证包含标注在连续转向中的保留、遮挡与故障恢复，模型请求与缓存隔离、迟到响应、缺测，以及桌面和手机的真实 Chrome 画面。

## 第二阶段

随后评估分层云并实现可行的显示近似，再加入雨雪动画。

Open-Meteo 已提供低、中、高云量，分别覆盖约 0—3 km、3—8 km、8 km 以上。当前模型仅区分云量与图案比例，未使用真实云底和空间场。可在现有射线合成中按不同示意高度、形态、颜色与透光区分三层，并让 CPU 透过率与 GPU 共享参数。高度与风场需按显示近似表达。[官方变量说明](https://open-meteo.com/en/docs)

雨雪动画采用独立于拍摄时刻的单调播放时间，雨下落快、雪下落慢并轻微横向漂移。页面隐藏、预览隐藏、关闭效果或无降水时停止连续重绘，恢复后平滑继续。动画不触发天气请求、天体计算或地形加载，尊重减少动态效果的系统偏好。

分层、地平线、高处机位、地形遮挡和雨雪逐帧变化分别验收。真实空间云场和实际云底仍需另行资料支持。

## 第二阶段执行记录

### 分层可行性与实施

2026-11-07 完成分层云与雨雪动画的本地实现和验收。现有接口提供独立的低、中、高云量，足以驱动可区分的三层显示。每层采用独立的水平尺度、伸展方向、细节比例、透光与配色，高云偏薄和条絮状，中云偏大片，低云更厚暗，按高、中、低顺序合成。CPU 透过率与 GPU 着色器共用同一份层参数，保留日月星空的云遮蔽。

来源的层云量不能直接推出云底。显示层取机位上方 1.5、5、10 km 作为示意距离，结合曲率约束远处投影，实际云高仍待资料支持。三层继续作为 DEM 后方的天空构图背景。接近地平线时，纹理细节和着色变化同时收敛到平均覆盖，保留既有条带修正。

### 动画与生命周期

雨滴较快下落，雪花较慢下落并轻微横向漂移，近地风影响显示倾斜。播放时间使用独立单调时钟，拍摄计划与天气采样时刻保持固定。静止场景按最多每秒 30 次的定时请求刷新，光照和云参数在场景变化时准备，逐帧复用。关闭天气、无降水、隐藏预览、页面转入后台、系统减少动态效果、渲染失败及卸载均停止动画定时器，恢复时从暂停的播放位置继续。
