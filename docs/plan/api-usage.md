# 外部服务用量

按用户 2026-11-11 的要求，核实 Open-Meteo 免费接口的限额与计数方式，评估其他外部服务的用量限制，并在界面显示 Open-Meteo 的用量。更新于 2026-11-11。

## Open-Meteo

- 免费接口（非商业）：每分钟 600 次、每小时 5,000 次、每天 10,000 次、每月 300,000 次。条款原文为“Rate limits are applied by IP addresses and application”。本站从访问者浏览器直连，因此每位访问者的公网 IP 各有一份额度，不是全站累计；同一出口 IP（公司、校园、运营商共享出口）以及该 IP 上其他使用 Open-Meteo 的应用合并计数。“application”如何识别未说明，滥用时可能整体封禁。
- 计费（2026-11-11 用响应头 `X-RateLimit-Cost` 实测）：
  - 每次 = 坐标数 × max(1, 变量数 × 模型数 / 10) × max(1, 天数 / 14)。
  - 天气预报（12 个变量、7 天）计 1.2 次；“自动匹配”来源识别（16 个模型、1 个变量）计 1.6 次；两个坐标计 2.0 次。
  - 潮位一次查询 13 个坐标，估计计 13 次。海洋接口不返回计费头，按同一规则估算。
- 服务端信息：预报接口返回 `X-RateLimit-Cost/Limit/Remaining/Reset/Window` 并允许跨域读取，但实测窗口为 60 秒，只给出同一 IP 本分钟的剩余。没有按日的余量，也没有免费用户的用量查询。

## 用量显示

- 本浏览器记账（`src/domain/api-usage.ts`、`src/preview/api-usage.ts`）：
  - 每次 Open-Meteo 响应按 `X-RateLimit-Cost` 计；缺这个头时按上面的规则估算。
  - 按分钟累加，存入本机 localStorage，同一浏览器的各标签页共用；超过一天的记录丢弃，存储不可用时只记在本页内存。
- 右栏“光照与环境”（开启天气或潮汐，或近 24 小时内有调用时）：
  - 常显：“Open-Meteo 用量（本浏览器）：近 24 小时约 N / 10,000 次”。服务端的日界不明，因此用滚动 24 小时。
  - 详细数值：近 1 小时、近 1 分钟、同一 IP 本分钟剩余、计数口径，以及每次读取的约计次数。
  - 任一窗口达到上限的 80% 时提示“接近免费上限”。
- 被限流（429）时，天气与潮位的错误写“Open-Meteo 限流：同一 IP 用量已满，约 N 秒后可重试”（取 `Retry-After`），用量行显示恢复倒计时。
- 看不到的部分：同一 IP 上其他设备与其他应用的用量；这一点在详细数值中写明。

## 其他外部服务

|---|---|---|---|
| Nominatim | 地点搜索 | 每秒最多 1 次，禁止批量与周期性查询 | 全站所有用户合计（“the sum of traffic by all your users”）；本页内已保证间隔 1.1 秒并缓存，用户多时需换自建或付费服务 |
| NOAA SWPC | 极光 | 未公布额度，响应缓存 60 秒 | 各访问者 IP；本地缓存 Kp 30 分钟，临近预报只在拍摄时刻接近现在时读取 |

| Mapterhorn | 地形 DEM | 免密钥，未找到公开额度或条款 | 待确认 |
| GitHub Pages | 本站静态文件（彗星目录、轨道快照、光污染分块、地标模型） | 软性限制：每月约 100 GB 流量、站点 1 GB | 全站合计 |

## 验证

- `npm test` 401 项全部通过。新增 `tests/api-usage.test.mjs`：
  - 计费估算与实测响应头一致。
  - 滚动窗口与过期丢弃。
  - 存储读取校验、`Retry-After` 解析。
  - 响应记账：使用计费头、缺头时估算、失败不计、429 记录与恢复。
- 交互检查：开启天气后出现用量行，记账后数字与详细数值更新，接近上限与限流分别提示，关闭天气后当天仍显示。
- Chrome：开启天气与潮汐后，真实请求记为 14.2 次（天气 1.2 + 潮汐 13），同一 IP 本分钟剩余 597.6。
- 没有实际触发 429；潮位按坐标计费是按预报接口推断。
