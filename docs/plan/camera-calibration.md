# 山峰投影与近地相机校准

本记录保留远山 LOD 修正前的相机校准。后续已修复下载与绘制细节策略不一致的问题，当前结果见[远山 DEM 验收](terrain-detail.md)；下表的 SDK 采样值描述当时版本。

更新：2026-11-04。状态：本轮相机测量与姿态联动修复已完成；真实地理精度尚未达标验收。

## 范围与判据

本轮沿用现有 DEM、平面地形与摄影相机，校准参考点投影和真实绘制眼点。暂不切换引擎、提高地形分辨率、修改水位、扩展网络恢复或其他天体。

1. 用日本气象厅的富士山剣ヶ峰参考坐标核对投影，同时保留参考高程和 DEM 高程；两者不能混为同一精度基准。
2. 以 MapLibre 公开的自定义图层矩阵反算真实渲染眼点，与请求眼点比较；分别检查 0.1 / 1.6 / 10 m 离地高度及广角、长焦。
3. 独立针孔投影与 SDK 公共投影应在 0.1 CSS px 内一致；同源平面模型的数值容差不代表真实地理精度。实际眼点偏移单独测量，发现防碰撞调整时明确反馈，不声称计划值就是实际值。
4. 区分渲染器误差、DEM/参考点差异和平面地球近似；有确定原因才修复，不按单张画面加偏移。保存固定输入、真实画面和待验边界。

开发服务通过 `?calibration=fuji` 启用只读校准信息；正常页面及生产构建不加载校准器。所有测量使用公共 API，不从浏览器读取 React 或 MapLibre 私有字段。

## 参考与执行结果

富士山参考：北纬 35°21′39″、东经 138°43′39″、高程 3776 m（剣ヶ峰测定点），[日本气象厅](https://www.data.jma.go.jp/vois/data/tokyo/314_Fujisan/314_index.html)。DEM 垂直基准仍须单独核对，不将该高程直接当作 DEM 的正确值。

测量实现见[相机校准设计](../architecture/camera-calibration.md)，既有结果见[地形验收](terrain-validation.md)。

## 自动检查

Windows、Node.js 24.17.0：`npm.cmd test` 的 80 项检查通过，`npm.cmd run build` 通过，保留既有 MapLibre 包体提示。新增 24 组相机配置（4 焦距 × 3 离地高度 × 横竖幅），检查公开矩阵反算眼点、独立参考点投影与 SDK 投影；既有相机与天体投影回归继续保留。球面对照检查赤道一度弦方向应低于水平面 0.5°，日期线采用最近世界副本。

## 发现、修复与精度边界

已修复：原预览只按计划姿态投影日月，未反映引擎防碰撞引起的高度和俯仰变化。现在读取实际相机、显示避让提示，并以实际姿态更新日月和预览读数。请求计划保持独立，未强制消除防碰撞调整。

仍有两类地理精度限制，不能通过本轮数学一致性校验宣布解决：

- DEM / LOD / 参考点：该点独立 z12 双线性采样为 3756.83 m，当前 SDK 查询随加载和视图出现 3755.02 m、3728.85 m，公布参考为 3776 m。插值、细节层级、垂直基准与坐标舍入尚未逐一排除。1000 mm 横幅中，采用公布高程与该次 SDK 查询值可相差约 99.81 px。这个差异不直接等于真实山峰误差。
- 平面与曲率：相同参考高程，平面 Mercator 与球面 ENU 模型在本机位 1000 mm 横幅中相差约 46.99 px；该球面对照也不是带实测大气与同一垂直基准的实景真值。

剣ヶ峰测定点不能等同于从山中湖看到的山脊最高像素；远侧地面点可能被近侧山脊遮挡。截图仅核对参考点所在区域、裁切与量级，未用这一个点宣布整条山脊精度通过。本轮没有米级地形、真实触山时刻或实拍对齐的精度承诺。

下一小步优先验证远山 DEM 的实际细节层级和采样一致性，再单独决定地球曲率处理；真实网络恢复、水位及其他天体仍是独立待办。
