# 机位保存与分享

2026-11-08 按用户要求实施第一步：本地保存多个机位、以分享码导入导出、刷新后恢复，以及页头机位菜单与任意时区选择。AI 生成机位（第二步）只完成设计，应用内意图解算暂缓。

[全局规划](overview.md)中暂缓的“分享”只收窄为本地保存加字符串分享；账户、云端保存与协作仍不在范围内。

## 用户决定

评估稿第 9 节的待决事项，用户已逐项答复：

| 事项 | 决定 |
| --- | --- |
| 天气与空间站 | 按应用时的实时数据显示，画面与保存时不同无需提示 |
| 构图线 | 不随机位保存 |
| 时区 | 开放任意 IANA 时区，并设计好选择界面 |
| 页头 | 删去“工作区原型”“P3 / 天文构图”和“摄影规划” |
| 刷新 | 刷新后恢复上次的工作状态 |
| AI | 格式说明对人尽可能隐蔽、对 AI 明确可见；应用内意图解析暂缓 |

## 1. 机位包含什么

机位覆盖拍摄计划的全部字段：

- 位置与相机离地高度；
- 方位与俯仰；
- 焦距、传感器、画幅比例、横竖幅、相机响应；
- UTC 时刻、显示时区、大气折射；
- 八个图层开关（含星座）；
- 银河对比度；
- 光污染、天气效果与预测模型。

**不包含：**构图线、地图浏览视角、面板布局、右栏展开与搜索。

- 应用机位后，地图按现有逻辑在机位离开视野时跟随。
- 右栏图层分组按新开关重新同步。
- 参数区丢弃尚未提交的输入草稿。

**防止漂移：**拍摄计划新增字段时，读取函数以 `satisfies Required<ShootingPlan>` 写出全部字段，图层列表也有类型穷举，漏写即编译失败；测试另以全字段不同于默认值的计划做往返。

**画面一致的边界：**天气与空间站使用应用时的实时数据，与保存时不同不作提示。普通建筑随 OpenStreetMap 更新可能小变。画布像素尺寸不同会影响 DEM 细化与标注避让。

## 2. 机位格式 v1

对外格式是语义分组的 JSON，与内部拍摄计划结构解耦。本地存储、刷新恢复、分享码和手写或 AI 生成的 JSON 共用同一套编解码（`src/domain/shot.ts`）。

```json
{
  "format": "tamatamatori.shot",
  "version": 1,
  "name": "富士 · 冬夜银河",
  "note": "",
  "position": { "latitude": 35.4172, "longitude": 138.8729, "heightAboveGround": 1.6 },
  "view": { "azimuth": 200, "pitch": 18 },
  "camera": { "focalLength": 24, "sensor": "full-frame", "aspectRatio": "3:2", "orientation": "landscape", "response": "stock" },
  "time": { "instant": "2026-11-12T14:40:00Z", "local": "2026-11-12T23:40:00", "timeZone": "Asia/Tokyo", "refraction": "standard" },
  "layers": { "buildings": false, "sun": true, "sunPath": false, "moon": true, "moonPath": false, "stars": true, "constellations": false, "milkyWay": true, "deepSky": true, "stations": false, "meteors": false, "meteorDensity": false },
  "sky": { "milkyWayContrast": 100 },
  "environment": { "lightPollution": false, "weather": false, "weatherModel": "best_match" }
}
```

### 读取规则

- **必填与默认：**
  - 必填 `format`、`version`、`position` 的经纬度、`view.azimuth`、`time`。
  - 其余缺省时取应用默认值，导入预览折叠显示“N 项未提供，已用默认值”。
  - 只给 `instant` 不给时区时，时区取 `UTC`。
- **报错而不猜测：**
  - 未知字段报错；`$schema` 允许并忽略，为第二步预留。
  - 超出范围报错，不截断。范围与参数区一致：纬度与俯仰 ±90、离地 0.1～100 m、焦距 8～1000 mm、银河对比度 25～200、年份 1900–2100。
  - 星座开启而星空关闭时报错；日月轨迹（`sunPath`、`moonPath`）开启而对应天体关闭时同样报错。轨迹字段于 2026-11-09 加入 v1，旧机位缺省为关闭（见[日月运行轨迹](sun-moon-paths.md)）。流星雨的 `meteors`、`meteorDensity` 同日加入，旧机位缺省为关闭；密度开启而图层关闭时报错（见[流星雨计划](meteor-showers.md)）。同日未发布的开发版曾写出拍摄时长 `sky.meteorHours`，改为整晚累计后读取时忽略、不再写出，这是“未知字段报错”的唯一例外。彗星图层 `comets` 于 2026-11-10 加入 v1，旧机位缺省为关闭（见[彗星计划](comets.md)）。
- **只归一不改值：**
  - 方位角与经度超出范围时取模归一。
  - 范围内的值原样保留：测试发现取模会把 123.456789 变成 123.45678900000001，已改为只处理越界值。
- **时间：**
  - 以 `instant`（UTC）为准。
  - 也接受只写 `local` 加 `timeZone`。两者都写时，`local` 必须按其写到的精度（分或秒）与 `instant` 一致。
  - 夏令时跳过或重复的当地时间报错。
- **时区：**只要浏览器与 Temporal 都接受的 IANA 时区即可，大小写自动规范（`europe/paris` → `Europe/Paris`）。
- **文本：**名称最多 40 字，备注最多 500 字，只作纯文本显示；整段输入上限 16 KB。
- **错误信息：**一次列出全部问题并带字段路径，例如 `view.azimuth：应为数字，收到 "西南"`。导入框提供“复制问题列表”，便于交回 AI 修正。
- **版本：**高于当前版本的机位拒绝导入，并提示刷新页面。

### 分享字符串

- **分享码：**`tmt1:` 加 base64url 编码的 UTF-8 JSON，单行、约 0.9–1.5 KB，导入时忽略空白与换行。
- **导入还接受：**
  - 纯 JSON，以及 Markdown 代码块包着的 JSON；
  - 带 `#shot=` 的链接，后接分享码或 `json:` 加 URL 编码的 JSON。

  链接目前只能粘贴进导入框；打开链接自动导入属于第二步。
- **导出：**分享对话框突出分享码，JSON 放在折叠的“JSON 格式”中。

## 3. 本地存储与刷新恢复

| 键 | 内容 |
| --- | --- |
| `tamatamatori.shots.v1` | `{ version: 1, shots: [{ id, createdAt, updatedAt, shot }] }`，最多 200 个 |
| `tamatamatori.session.v1` | `{ version: 1, activeId, shot }`：当前工作状态与关联的已保存机位 |

**机位库（`src/domain/shot-library.ts`）：**

- 本地存储不可用时，禁用保存，分享与“仅应用”照常可用。
- 配额不足时明确报错，不做部分写入。
- 整体损坏时进入只读状态，不自动覆盖；用户可确认后清空。
- 单个条目损坏时，该条原样保留，显示“无法读取”并可删除。
- 其他标签页修改后，通过 `storage` 事件刷新列表。

**刷新恢复：**

- 工作状态变化后 300 ms 写入，页面隐藏时立即补写。
- 启动时校验会话；有效则恢复，无效则安静回退到默认机位，不影响已保存的机位。
- 地图初始中心随恢复的机位。
- 面板布局、构图线和右栏状态不恢复。

**同源说明：**`imanity.github.io` 下的所有 GitHub Pages 项目共用一份本地存储。键名带应用前缀，About 新增“本地保存”说明。

## 4. 界面

### 页头

只保留品牌、机位按钮与 About。机位按钮显示：

- 当前机位名称，或“未保存的机位”；
- 与关联机位不同时，加一个橙色圆点，读屏文本为“已修改”；
- 窄屏时按钮随可用宽度截断，并隐藏下拉箭头。

### 机位面板

非模态面板，Escape 或点击外部关闭，焦点回到按钮；窄屏改为页头下方全宽面板。

- **当前机位：**名称与状态（尚未保存 / 已保存 / 已修改）。
  - “保存修改”覆盖关联机位并移到列表顶部。
  - “保存为机位”或“另存为新机位”在面板内填写名称，默认名为“最近已接入地标或坐标 · 月-日 时:分”。
  - “分享”打开分享对话框。
- **已保存列表：**按最近更新排序，每行显示名称、地点、当地时间与时区、镜头。
  - 点击一行即应用。
  - “···”展开重命名、分享、删除。删除后在面板内显示“已删除 · 撤销”。
- **底部：**“导入机位”和“机位只保存在此浏览器”。

### 导入与应用

- **导入对话框：**粘贴后即时解析。
  - 出错时列出带路径的问题，并提供“复制问题列表”。
  - 成功时显示地点、时间、方向、镜头、图层摘要，名称可改。
  - 提供“仅应用”与“保存并应用”。
- **应用机位：**一次替换整个拍摄计划，不弹确认框。
  - 页头下方提示“已应用「名称」”，附“撤销”。撤销恢复应用前的完整状态与关联机位。
  - 提示 12 秒后消失；鼠标悬停或键盘焦点在提示内时暂停计时。

### 时区选择

参数区“显示时区”改为一个类似下拉框的按钮，显示“城市 · UTC 偏移”，悬停可见完整 IANA 名称。点开后在本行下方展开搜索框与列表；列表浮在参数区内，不会被滚动容器裁切。

- **未输入时：**
  - “常用”分组列出当前时区、浏览器所在时区、北京、东京、UTC、伦敦、纽约。
  - 其后以分隔线接全部时区，按拍摄时刻的 UTC 偏移排列，约 420 个。原“全部时区”标题已于 2026-11-09 删去，见[拍摄参数交互优化](parameter-controls.md)。
- **搜索：**
  - 支持 45 个常用城市的中文名、英文城市名、IANA 名称、中文时区通称（如“中欧”）和偏移（`+9`、`UTC+5:30`、`GMT-4`）。
  - 最多显示 80 条，其余提示继续输入。
  - 偏移按拍摄时刻计算，因此夏令时正确：纽约 7 月为 UTC−4，1 月为 UTC−5。
- **键盘：**上下键、翻页、Home/End、回车选择；Escape 关闭且不改时区；当前时区带勾。
- **行为：**只改变显示时区，不改变拍摄时刻。
- **列表名称：**ICU 仍以旧名列出的时区（`Asia/Calcutta` 等）换成现名（`Asia/Kolkata`）。
- **限制：**没有按机位推断时区的边界数据，时区仍由用户选择。

## 5. AI 生成机位（第二步，仅设计）

**目标：**普通用户界面不出现格式说明，也不提供“复制给 AI 的说明”按钮；AI 读取站点或机位时能明确找到说明。

**发布说明文件：**

- 站点发布 `/Tamatamatori/llms.txt` 入口、`shot-format.md` 说明与 `shot.schema.json`。
- 页面上不放链接，只在 `index.html` 头部用 `<link rel="alternate" type="text/markdown">` 指向说明。
- 说明与 schema 的字段、范围和枚举由代码常量生成，测试保证不漂移。

**让 AI 找到说明：**

- 导出的 JSON 加 `$schema` 绝对地址。用户把导出的 JSON 交给 AI 作示例时，AI 能顺着地址读到完整格式。
- 分享字符串改为站点链接 `https://imanity.github.io/Tamatamatori/#shot=tmt1:…`，人点开即可导入，AI 也能从域名找到说明。
- 打开带 `#shot=` 的链接时，先显示与导入相同的预览，确认后再应用，然后清除地址中的 hash；hash 不会发送给服务器。
- AI 可以直接回复 `#shot=json:` 加 URL 编码 JSON 的链接，因为 AI 写 base64 容易出错。

**不建议页面隐藏文字：**有些抓取工具会忽略隐藏内容；而针对 AI 的隐藏文字也可能被当作提示注入。如需保留，内容只写成描述性文档，不写成命令。

**暂缓：**应用内意图解析（`view.aim`、`time.event`）与页面内直接对话 AI。

## 7. 限制与下一步

**限制：**

- 画面一致只在同一应用版本、同一面板尺寸、确定性图层下验证。天气、空间站和每周更新的建筑数据按应用时的数据绘制。
- 刷新不恢复面板布局、构图线、右栏展开与地图缩放。
- 时区不随机位自动推断。
- 机位只在此浏览器，不跨设备同步。
- 未测实体手机。

**下一步：**第二步 AI 说明与链接导入，见第 5 节。
