# 地球曲率与观测方向对照

本篇保留初始模型比较结果。后续[实际空间投影修正](terrain-perspective.md)已接入默认网格、水体及日月共享深度；下文“尚未实现”的状态属于初期验证轮次。

更新：2026-11-04。状态：独立数值基准、Chrome 模型对照和构建通过；正式地形曲率与实景精度未实现/未验收。

## 本轮范围

接续[远山 DEM 验收](terrain-detail.md)，建立独立 WGS84 ECEF → 局部东、北、天（ENU）的数值基准，对比现有 Mercator 平面与平均半径球面。先验证模型影响，不修改正式地形网格、相机约束、日月圆盘或深度遮挡，不迁移引擎。

## 验收方式

- 对照权威坐标约定和独立 PROJ 输出，固定近、中、远、高纬度、日期变更线及垂直方向输入；测试不依赖联网或 Python 环境。
- 使用同一实际眼点、同一目标高程和镜头投影，分别记录完整模型差异与固定水平分量时的垂直曲率分量，避免把 Mercator 尺度、椭球方向或 DEM 高程差全部叫作曲率。
- 在开发校准页核对富士山固定点，覆盖广角、长焦与横竖幅，保存真实 Chrome 数值及截图；正式页面不显示诊断。
- 核实 DEM 高程来源及垂直基准。未确认转换时，仅作“输入高程暂视为椭球高”的条件比较，不能宣称实景精度或曲率已加入地形。

计算约定、高程基准调查和样本复现见[曲率参考设计](../architecture/curvature-reference.md)。

## 独立数值验证

新增 4 项自动检查，当前共 89 项通过；`npm.cmd run test:terrain`、`npm.cmd test` 和 `npm.cmd run build` 通过。构建仍有原有 MapLibre 大包提示。生产 JS 不包含椭球计算器或开发诊断文案。

使用 pyproj 3.7.2 / PROJ 9.5.1 独立生成 9 组离线 ECEF/ENU 样本，TypeScript 每轴与之差异小于 0.000001 m；另对照 PROJ 文档的毫米取整输出。覆盖近中远、富士山条件输入、日期变更线、高纬度、南半球、垂直方向，并用解析值检查赤道轴和极点。此阈值只是计算一致性，不是 DEM 或真实地理精度。

固定合成场景：眼点 35.4172 / 138.8729，椭球高 1000 m，沿 WGS84 测地线方位 247° 放置同高目标；相机方位 247°、俯仰 0°，全画幅 3:2 横幅、1000 mm、1152×768。未使用真实地形，也未测试这些合成点的可见性。完整结果见 [controlled-models.json](curvature-evidence/controlled-models.json)。

## Chrome 固定场景

真实 Chrome / WebGL，MapLibre 6.16.0 及既有 LOD 兼容修正。本轮使用独立开发服务 5174，未关闭用户已有的 5173 服务。六组快照均为 `areTilesLoaded() = true`，见 [measurements.json](curvature-evidence/measurements.json)。

山中湖机位 35.4172 / 138.8729，DEM 980.5 m，计划离地 1.6 m，实际眼点高约 982.100925 m。固定方位 244.567755725°、俯仰 10.768041897°，2026-11-04 17:00 / Asia/Tokyo；全画幅 3:2。目标沿用剣ヶ峰参考坐标，比较双方均采用当前 SDK 的同一目标 DEM 值；两端输入高程仅临时视为椭球高。

像素向右/下为正。8/35 mm 的目标 DEM 为 z11 的 3756.169347 m，其余为 z12 的 3756.825398 m；每一行两种模型使用相同值。1000 mm 往返恢复后结果一致，SDK 与同高程平面基准差小于 0.000001 CSS px，只表明计算与当前渲染模型一致。截图：[横幅](curvature-evidence/fuji-1000-models.jpg)、[竖幅](curvature-evidence/fuji-1000-portrait.jpg)。

1000 mm 横幅的完整方向差为方位 +0.141227399°、高度角 −0.088121573°。保持椭球 E/N，仅比较垂直分量时，曲率下降约 16.750850 m，对应向下 35.3872 px；它与上表完整 Δy 不相等。平均半径球面、椭球和 Mercator 的水平尺度、方向均有差别，先前约 46.99 px 的球面/平面公布高程对照不能当作最终椭球校正量。

开发页的绿色十字与数值摘要已在实际画面出现。参考点处于山体内部仍可能是远侧山脊遮挡，不能拿最高轮廓对齐来判定正确位置。退出校准 URL 后正常页面不显示标记或诊断；控制台未捕获 error。

## 保留边界与下一步

目前只验证了“模型差异值得处理”，没有把绿色标记变成真实曲率地形。Mapterhorn 逐瓦片来源/垂直转换仍未确认，公布高程也不是可直接使用的 WGS84 椭球高；未加入地面大气折射或现场控制照片。不能声称这些像素量就是用户实拍误差，也未重新验收全球覆盖、真实网络失败恢复或触屏。

下一小步建议做局部 ENU 的真实曲面地形原型：先固定同一 DEM 和机位，保持相机与日月方向基准一致，检查山脊及水体形状、共享深度与遮挡，再决定正式渲染路径。进入该轮前先核实可用的垂直基准转换；当前不迁移引擎或为匹配截图加入经验修正。

后续[高程基准核查](elevation-datum-audit.md)已完成：现有证据不支持正式自动转换；开发原型可在明确高度假设下先验证实际网格几何，不等待全球基准统一。具体拆步及准入条件以该记录和[高度基准决策](../architecture/elevation-datum.md)为准。
