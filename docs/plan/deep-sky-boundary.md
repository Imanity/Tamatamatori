# 深空影像边界与背景星场

2026-11-06。用户指出 M45/M8/NGC7000 的矩形边界明显，并询问 M31/M42 为何不同。本轮只修正这三图的深空扩散光与背景星场混合，不新增天体目录、天空模型或曝光参数。

## 原因

M31/M42 最终 RGB 仍经过星点抑制，来源外沿也较暗，亮度驱动的透明度会自然接近零。新三图为恢复长焦细节改成完整原图 RGB；密集恒星在照片范围内被叠加，照片外却没有同一星场。背景扣除只处理了低频底色，40 像素淡出只处理了很窄的照片边缘，均无法匹配星点密度。这个差别来自数据与处理策略，不是地图相机或 UV 布局错误。

## 本轮方案

深空层的透明度应反映星云扩散结构，而非整张照片内的所有亮像素。由原始颜色中的发射/反射优势信号取得扩散光支持，经形态重建保留与大片云气连通的细丝、抑制紧凑点源；只平滑支持图，原始 RGB 细节不做全图模糊。颜色比例和改机红色增量均接受同一连续支持，不使用固定椭圆、不生成来源之外的云气。

照片中的白色星核不能在支持图中变成圆洞；对小孔处理只影响透明度支持，不在 RGB 影像中填补或生成纹理。恒星图层与 M45 关联 HYG 点源继续独立定位。此方法是显示分离近似，不称为实测去星或谱线提取；星云内部可能仍保留照片星点。

## 验收

- 保存当前 5f9bebb 图集与页面作为对照，用 M45/M8 600 mm、北美 200 mm 查看整幅资料边界；M31/M42 保留为像素不变的对照组。
- 1000 mm 检查细丝、暗带及星核附近，不以再次抹平结构换取隐藏边界；沿用固定裁区的清晰度回归。
- 检查来源边缘背景星场能量明显下降，星云主体保留连续结构；数值指标与真实 Chrome 画面分别记录。
- 检查支持图的小孔、发射/反射两类、改机独立性、白昼与 DEM 遮挡；完成匹配测试、独立 WCS 与子路径构建。
- 不把有限资料包装成完整实测天空；若仍能看出来源边界或星点残留，如实记录。

## 执行结果

本地验收完成于 2026-11-06。三图以原始线性颜色的反射/发射优势取得支持，9 像素腐蚀后形态重建保留连通细丝；41 像素闭运算避免白色星核产生孔洞，sigma=2 仅平滑支持。最终 RGB 仍保留原图高频，基础色彩与额外红色增量同时接受支持；HYG、天球投影和运行时 shader 未改。

- `npm test`：156/156 通过。新增直接解码 PNG 的外围/主体信号回归，沿用长焦细节回归；M31、M42、加州、心脏、灵魂的 RGBA 哈希完全不变。
- 独立 PyAVM/Astropy/WCSLIB 125 点及完整来源足迹通过，最大转换差 5.30e−11 个参考像素；另用反射/发射两类合成支持检查孤立点源消失、连通窄丝保留和白色星核不留孔洞。这些不代替 GPU 或实景标定。见[配准与合成记录](deep-sky-boundary-evidence/image-registration.json)。
- `npm run build -- --base /Tamatamatori/` 通过，包含类型检查；保留既有大分块提示，无新增依赖。
- 最终 atlas 4096×4096、6300888 bytes（约 6.01 MiB），SHA256 `0886bc897a7a98bcb83606ae22468eecf4d57dd20fb402018232456384f7c304`。压缩体积下降，GPU RGBA/mip 仍约 85 MiB；设备回退、按需加载与失败处理未改。
