2026-11-08，按用户要求把集中下载的 18 份模型全部接入现有批量流程，并在拍摄预览中逐个检查近景、远景和失败回退画面。开始时工作区干净（`6c1f9a0`）。本轮沿用无纹理、不透明共享光照、TTLM 1 资源和 30 万面全场预算，不增加后端、纹理、玻璃、夜景灯光或整城精模；不默认提交推送。

## 范围与验收方式

1. 以文件内嵌元数据和 Sketchfab 公开 API 逐份核对实际下载的作者、页面与 CC BY 4.0 许可；与候选清单不一致时按实际文件登记，不沿用候选信息。
2. 逐份确定坐标框架、竖直轴、需排除的非建筑几何、官方总高和中心；用 OpenFreeMap / OSM 建筑分部做多高度层俯视轮廓拟合，得到锚点与朝向，并按覆盖率确定近景要替换的粗分部及 `partRadius`。
3. 一条命令批量制作，逐项通过六方向 CPU 覆盖、预算和哈希检查后成组集成；既有三处地标的资源哈希必须不变。
4. 真实 MVT 的 CPU 回放确认近景替换逻辑；真实 Chrome（本机 GPU）按固定场景截图：两处近景、25 km 长焦远景，以及拦截模型请求后的 OSM 粗体块对照。
5. 自动测试、类型检查和 `/Tamatamatori/` 子路径构建全部执行。

不处理：模型自身的造型误差修正（后续经用户确认，已另行完成三处，见[造型修正](#造型修正v2)）、实体手机与帧率、纹理/夜景、整城精模及区域本地包。

## 流水线调整

为接入这批文件，转换器新增三个必须在配方中显式登记的选项，未登记时行为与此前完全相同；既有三处地标重新制作后压缩与解压哈希不变：

- `processing.excludeNodes`：按节点名排除地面、湖面、背景竖板等非建筑几何；每个名称必须实际命中，排除的节点数与三角面计入清单 `selection`。
- `processing.ignoreLinePrimitives`：忽略 SketchUp 导出的边线等点/线图元；未开启时仍拒绝。检查命令改为报告线图元数量而非直接失败。
- `processing.dropDuplicateTriangles` 与可选 `backMaterials`：删除顶点位置完全相同的重合反向面（双面导出），重复时优先保留非背面材质。几何轮廓无损，删除数量计入 `selection`。

另修正两处：目标面数大于输入时夹到输入面数，避免简化器断言；六方向覆盖检查原先只搜索 4 像素邻域，对小体量模型（0.04 m/像素）实际门槛只有 16 cm，与文档的 1 m 容差不符，现改为精确欧氏距离变换。21 份模型新旧检查的输出逐字节一致，只是不再错误拒绝亚米差异。

运行时地标着色改为双面光照：法线背向观察者时翻转，只作用于地标网格，普通体块不变。重合反向面去重后保留哪一面、薄壳和桁架的背面都能按朝向观察者的一侧受光；几何、深度和预算不变。

## 东方明珠替换（v2）

同日，用户另行下载 `oriental_pearl_shanghai..glb` 替换 v1。内嵌元数据与 Sketchfab 公开 API 一致：drosovila「Oriental Pearl, Shanghai.」（2016），**CC BY-NC 4.0，仅限非商业使用**。v1 从未发布，因此 v2 直接替换，未保留 v1 资源。

- 许可：流程原先只接受 CC BY 4.0 / CC0 1.0。按项目已有非商业数据（光污染图集、Open-Meteo 免费服务）的先例，许可表加入 CC BY-NC 4.0，限制由生成器写入目录 `credit.use`，About 在许可与下载入口旁显示，`CREDITS.txt` 同步标注。`draft` 按候选许可标识预填，不再一律写成 CC BY 4.0。若之后要商业使用，这一模型须撤下或另行取得授权。
- 文件：单网格 7,657 顶点 / 5,063 面，原有 alpha 镂空纹理（截断值 0.83）。按纹理采样，168 个面大半透明，位于上球与太空舱之间的筒身及一段天线；去纹理后这些部位为实心，直径不变。没有地面板或背景几何，无需 `excludeNodes`，面数低于预算，未减面。
- 定位：网格原点与天线轴线相差约 4 cm，因此以原点为中心；锚点取 OSM 三根立柱与各层球体分部的共同中心。朝向由三根立柱、三根斜撑脚的方位与 OSM 拟合，为 ENU 逆时针 99.25°，残差约 ±3°。多层俯视 IoU 对朝向不敏感：99.25°、219.25°、339.25° 得分相同（0.660–0.662），主体三重对称，只有模型塔座的入口坡道朝向随之变化，OSM 隐藏的塔座轮廓无法核实它。
- 比例：与 OSM 分层相比，下球约 70–125 m、直径约 52 m（OSM 72–121 m、约 48 m，官方约 50 m），上球约 250–300 m（OSM 252–298 m），天线顶 468 m。剩余偏差：太空舱直径约 19 m，比 OSM 约 11 m 偏大；斜撑落地半径约 60 m（OSM 约 55 m），立柱中心距轴约 10.5 m（OSM 约 9.3 m）。已写入注册说明。
- 着色：下球观景环带上下各两圈面，源模型用的是平直法线，其余球面为平滑法线。斜射阳光下，200 mm 以上的长焦近景可见斜向明暗条纹。已逐面核对：几何没有重叠或缺面；本轮未改法线。

CPU：六方向覆盖 IoU 1.0000（未减面）；真实 MVT 回放中 34 个粗分部全部确认，上海三处同场均为“已应用”，共 66,695 面。GPU：同一生产构建与 Chrome 下拍摄 11 个场景，均符合预期（应用 10 个、拦截后回退 1 个）。场景包括南、东、西北近景，外滩隔江 37 mm，200 mm 塔座与上部，两组 600 mm 下球环带，以及西南 25 km、西北 25 km 远景，见[六联图](landmark-batch-evidence/oriental-pearl-gpu.jpg)与[记录](landmark-batch-evidence/oriental-pearl-gpu.json)。隔江视角中斜撑与立柱着地，塔座贴地，球体位置与拦截后的 OSM 分层体块重合。`gpu-scenes.json` 中东方明珠的四个场景属于 v1，已由该记录替代。About 显示见[截图](landmark-batch-evidence/about-oriental-pearl.jpg)。v2 已用 `record-visual` 登记为画面通过。

## 已知限制与下一步

模型均为社区外观模型，定位与朝向近似，不提供测绘精度；高程沿用同源 DEM，不套 geoid 常数。双面光照只改光照，不改变遮挡或深度。手机检查使用 Chrome 视口仿真，未测实体手机与 GPU 帧耗时；纽约五座同场时普通建筑仅剩约 12.5 万面，覆盖会更稀疏。造型修正只按登记的参考尺寸调整整体比例或部件位置，不能恢复源模型没有的细节，也不构成测绘重建；修正前后的数值与画面已分开记录；东方明珠 v2 为非商业许可，商业使用前须撤下或另行授权；注册辅助脚本本轮为临时工具，若后续继续批量接入，可将多层轮廓拟合与分部筛选并入 `npm run landmarks` 并补测试。
