# 空间站轨道与快照

轨道输入使用 GP JSON 中的 UTC 历元和平均轨道根数，经 satellite.js 7.1.0 的 SGP4 转为 TEME，再按同一 UTC 的 GMST 转为地固坐标。观察点采用 WGS84 经度、纬度及当前预览相机高度，地平向量统一为 ENU。SGP4 的误差、地球定向近似与 DEM 未知垂直基准继续分别表达。

轨道加载状态独立于拍摄计划。快照更新不改变时间、机位、焦距或朝向，新的轨道版本使空间站绘制和遮挡查询一起失效。空间站标记及轨迹复用现有星空 GPU 深度与实际相机投影，标记大小属于构图辅助。

上游获取由构建脚本完成。固定主机和目标白名单、响应校验、超时、请求间隔、最近有效快照以及失败停用信息一起持久化。网页只读同源静态文件，保留本地有效缓存，不能把缓存到达时间当作轨道历元。具体策略和来源见[首步计划](../plan/space-stations.md)。

## 更新与发布

CI 的 Node.js 24 发布任务恢复 `.cache/station-feed.json`，在请求前持久化尝试时间，成功后保存最新有效元素。每次任务使用唯一缓存键，后续任务通过前缀恢复最近记录。缓存丢失时再参考已发布快照的检查时间。主分支任务串行执行，PR 任务继续支持取消旧执行。

上游错误进入暂停状态，错误信息和旧数据一并发布。维护者排查后通过手动工作流的 `resume_orbits` 恢复，恢复请求仍受两小时冷却限制。本地入口为 `npm run update:orbits`，缓存放在已忽略的 `.cache/` 中。

网页每五分钟检查同源 JSON，30 秒内限制重复手动检查。切换后台暂停新检查，关闭图层并结束空间站搜索时取消请求。迟到响应、快照检查时间回退及轨道历元回退均保留较新的有效状态。搜索可以先取得轨道，显式朝向才修改计划。

## 坐标与渲染边界

时间使用 UTC，TEME 到地固转换采用 GMST82 近似，UT1 按 UTC 处理，极移留在误差边界内。观察点高度与预览实际相机一致，毫米取整用于稳定计算缓存。DEM 的未知垂直基准沿用既有项目记录。

SGP4 使用 WGS72 传播常数，观察点转换采用 WGS84。32 组独立 C++ SGP4／ERFA 对照分别覆盖两站、跨日、日期变更线、近极区与负高程。实现间差异和实际轨道解误差分别记录。

空间站采用固定大小的方向环，轨迹点沿用同一地形深度。地影使用依赖库的太阳与阴影几何估计，右侧给出日照参考。标记在白昼和地影中均可作为构图辅助。相机视场、遮挡和参考标记的显示亮度分别表达。

satellite.js 7.1.0 的入口同时导出 ESM Worker 能力，Vite 使用 `worker.format = "es"` 以完成生产打包。本轮调用 JavaScript SGP4，最终产物经过 tree-shaking，发布目录中仅有实际地图 Worker，WASM 产物数量为零。生产构建的地图与独立地形实例已纳入浏览器验收。
