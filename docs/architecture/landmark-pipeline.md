# 地标制作数据流

制作使用已有 Node.js、glTF Transform 和 meshoptimizer，应用继续只加载 TTLM 1。增加的是离线数据流程，不引入运行时插件系统。

## 文件职责

- `landmarks/recipes/*.json`：人工核查后的单模型配方，是来源、几何框架、尺度、锚点、替换分部和预算的唯一编辑入口。
- `landmarks/registry.json`：已集成模型、对应配方/资源身份以及 CPU/画面验证状态。
- `.cache/landmarks/`：原始输入、检查报告、暂存产物、参考几何和批次报告，不发布或提交原始下载。
- `public/landmarks/`：已核对的压缩几何和完整出处清单。
- `src/data/landmarks.generated.json`：从配方、注册记录和实际产物生成的运行时目录，禁止手改。About 从同一份目录提供作者和逐模型下载。

许可在转换库的固定表中登记：CC BY 4.0、CC0 1.0 与 CC BY-NC 4.0，配方链接须与表一致。表中带使用限制的许可（目前仅非商业）由生成器写入目录 `credit.use` 和署名文件，About 在许可与下载入口旁显示；其他许可不生成该字段。扩充许可须同时改表并补测试，不在单个配方或界面中特判。

## 准入顺序

扫描/检查 → 人工确认配方 → 批量构建 → CPU 覆盖与预算检查 → 预览集成差异 → 集成 → 独立画面验收。

源文件按 SHA-256 匹配，文件名仅辅助识别。转换显式选择世界/局部框架及有符号轴，使用正确的法线变换与反射绕序；坐标单位、朝向与地面锚点不从文件名推断。仅处理静态自包含 GLB，未支持的依赖或变形须先离线烘焙。转换失败、超限或缺少人工核查时只输出报告。

源文件中的非建筑几何只能由配方显式处理：`excludeNodes` 按节点名排除地面、水面或背景板，名称必须实际命中；`ignoreLinePrimitives` 忽略导出的边线；`dropDuplicateTriangles` 删除顶点位置完全相同的重合反向面，可用 `backMaterials` 指定重复时让位的背面材质。三者都把数量写入清单 `selection`，未登记时行为不变，不自动猜测哪些部分不属于建筑。

来源造型偏差只能用配方顶层的 `corrections` 修正，不手改生成资源、目录或 About。修正在模型框架中执行：单位为米，水平原点为 `frame.center`，最低点为 0，坐标轴取 `frame.axes` 之后、朝向旋转之前。执行时机在缩放之后、焊接与减面之前，按登记顺序进行，最多 8 条，支持三种操作：

- `scale`：绕指定点各向缩放，系数 0.5–2。
- `remap`：沿 x/y/z 某一轴做单调分段线性重映射，各段斜率 0.5–2，两端按端段斜率外推。
- `translate`：按节点名平移，位移 ≤500 m。

位置变换后，法线按逆转置变换并归一化；重映射在内部断点处取两侧斜率的平均。每条修正须写明依据（OSM 分部或官方尺寸）。选择的节点必须存在且未被排除，结果须落在 0 至登记总高之内，否则制作失败。清单记录 `corrections` 与各条命中的顶点数，`verify` 发现修正参数漂移时拒绝。生成器把依据写入 About 与署名文件的加工说明，覆盖检查对比修正后的完整网格与减面结果。修正属于几何变化，须提高版本号并重新做画面验收；它不构成测绘重建。

集成前验证整个写入计划，已有模型保持，逐项校验源/配方/产物身份；写入采用同目录临时文件替换并保留回滚数据，进程内异常恢复已写文件。它不是跨文件的断电事务；异常退出后须重新 `verify`，通过后才能提交。集成与画面验收分开，用户允许暂缓浏览器时保留“画面待验”状态。`verify` 对照登记内容重新生成预期目录与版权摘要，并核对公开文件哈希，无需访问上游或原始文件。构建命令已先运行该校验，因此现有 CI 无需下载原模型。

运行时先按距离筛选已注册地标，再按登记且核对过的实际面数扣除 300,000 面场景预算；剩余预算不足时不请求该模型，并表达原因。单资源上限 128,000 顶点 / 100,000 面 / 2 MiB 压缩 / 4 MiB 解压。东京塔为保留细桁架将顶点门槛从 80,000 调高，其余上限不变。模型缓存继续受 8 MiB 几何预算约束，并最多保留 16 个条目；缓存驻留不等于当前场景 GPU 驻留。当前 21 份资源合计约 27.0 MiB 解压，同城最多五份（纽约约 7.3 MiB，仍在 8 MiB 缓存内）；跨城市加载会淘汰较旧资源，不无限累积。

近景替换先核对源瓦片、分部 ID、顶高、底高及空间范围；粗分部可登记跨瓦片位置，确认键包含瓦片和 ID。未确认的分部不被删除，空对应表不能通过 `every([])` 假称已确认；没有粗分部登记的模型只能在普通建筑窗口之外应用。单模型失败继续其他目标及普通体块；模型变化后沿用既有深度失效流程。实际 GPU 和性能另行验收。

## 更新身份

源文件内容和完整配方分别计算 SHA-256，配方按排序后的 JSON 值计算，避免 CRLF 或缩进差异。资产的压缩、解压哈希和确切长度随目录一起生成；注册记录另存地理位置/替换对应身份。几何或位置变化必须提升资源版本并清除旧画面通过状态；仅署名说明变更可保留既有几何验收。所有暂存结果仍须对应当前配方，不接受过时成功记录。

CPU 覆盖检查用源与减面后网格独立栅格化六个正交侧视角，水平窗口随模型范围自适应，要求 IoU ≥0.98 且栅格覆盖差距 ≤1 m；差距用精确欧氏距离变换计算，与栅格分辨率无关；分辨率不足一米/像素的横向大模型拒绝并要求单独处理。

运行时地标网格使用双面光照：法线背向观察者时翻转，薄壳、桁架和重合面去重后保留的任一面都按观察者一侧受光；普通体块的着色、深度、遮挡和预算不变。它验证制作过程的轮廓保真度，不验证真实楼高、WGS84 注册或渲染器。`record-visual` 仅登记人已核查的实际截图及当前几何/定位身份，不执行或伪造浏览器验证。完整操作与东京塔例子见[制作流程](../plan/landmark-pipeline.md)。
