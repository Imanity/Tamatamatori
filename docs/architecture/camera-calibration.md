# 摄影相机实际姿态与校准

更新：2026-11-04。目标是识别引擎约束后的实际相机，并保持地形、日月和读数一致；不修改用户计划来掩盖偏移。

## 实际相机

MapLibre 的近地防碰撞会抬高眼点并改变俯仰。`calculateCameraOptionsFromTo` 的返回值和输入的 DEM 加离地高度是请求值，不能直接当作最终绘制值。日月三维图层从公开 `CustomRenderMethodInput.modelViewProjectionMatrix` 读取绘制矩阵，以 `clip.x = clip.y = clip.w = 0` 的三个线性方程反算光心；Mercator 世界 XY 像素按公开 `getZoom()` 换算经纬度，Z 为米。矩阵保持双精度，角度从公开 `getPitch()`、`getBearing()` 获取，不读取私有变换或 GPU 纹理。

实际眼点带拍摄计划键返回 React；旧计划结果不能作为当前值。预览读数、方向参考、日月名称使用实际姿态；物理日月圆盘也按相同的公开角度投影。地图和参数保留请求计划。实际高度与请求差超过 0.02 m，或俯仰差超过 0.0001° 时显示“引擎避让”，同时列出实际离地近似值、实际俯仰与计划俯仰；阈值用于排除浮点噪声，不是地理精度承诺。实际离地仍相对当前 DEM 采样面，不能解释为现场测量值。

不关闭引擎防穿地，也不循环写回实际高度改变计划。地形加载、相机变化和重建后重新读取实际矩阵；失败保留具体错误与重试。星历测站仍沿用原有椭球面高度近似，不把这次读取的 DEM 高程混入天文算法。

## 开发校准器

仅在开发服务带 `?calibration=fuji` 时加载只读校准层，生产构建去除该层和参考点。校准层不执行 GL 绘制、读像素或修改相机；显示实际光心、独立针孔投影、SDK `project()`、绘制矩阵投影和参考点标记。它额外采样一个固定参考点的 z12 DEM，卸载时取消请求。

- 独立平面基准按机位经纬度计算 Mercator 水平位移，按引擎中心纬度换算米，垂直使用目标高程减眼点高程，再做三维针孔投影。
- SDK 投影采用当前地形查询值；矩阵投影采用相同坐标、高程，核对坐标约定和实际姿态。数值一致只说明同一平面模型一致，不能证明山峰的真实像素位置。
- 同时保留公开参考高程、固定 z12 双线性高程及当前 SDK 高程；LOD、插值、基准和参考点坐标精度可能不同。
- 球面对照采用半径 6371008.8 m 的球体和局部东、北、天方向，只量化模型差异，不作为测绘基准；不加入地面大气折射。平面与球面差异不能用截图经验偏移修正。

富士山剣ヶ峰的公开点不等于从所有方向可见的山脊最高像素，远侧点还可能被近侧山脊遮住。标记落在山体内部不能单独判定投影出错；正式地理精度验收需要同基准控制点或实测照片。

参考：[MapLibre 自定义图层输入](https://maplibre.org/maplibre-gl-js/docs/API/type-aliases/CustomRenderMethodInput/)、[Map API](https://maplibre.org/maplibre-gl-js/docs/API/classes/Map/)、[日本气象厅富士山参考](https://www.data.jma.go.jp/vois/data/tokyo/314_Fujisan/314_index.html)。坐标与矩阵语义同时对照当前安装的 SDK 6.16.0 源码和 CPU 验证。执行结果见[相机校准记录](../plan/camera-calibration.md)。
