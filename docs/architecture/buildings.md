# 建筑体块架构

首步从 OpenFreeMap TileJSON 解析版本化 xyz MVT 模板，按机位选择 z14 有限区域：约 5 km、最多 48 瓦片，2 km 内普通建筑，2–5 km 保留源高度至少 20 m 的分部。范围按源足迹边界相交选择，少数大建筑足迹可延伸越过约 5 km。建筑是拍摄计划的显示意图，网络与网格状态独立保存。当前窗口与缓存分别有预算，不在拍摄计划中存瓦片或 GL 对象。

独立模块解析 `building` 层，遵守 `hide_3d`，过滤缺失或异常的渲染高度，保留多多边形、孔洞与分部。有限瓦片可能含缓冲区和裁切边缘，要避免重复边缘几何，并明确分片模型的近似。每块网格使用瓦片局部坐标，配合现有 `photoTileFrame`、共享投影 GLSL 和摄影矩阵绘制，片元写入与 DEM 相同的对数深度。

片元按瓦片核心范围裁切缓冲区，省略恰好沿瓦片边界的竖墙，避免重复外壳与人为内墙。跨瓦片对象的分片基座仍可能在坡地出现高程差；首步未重建完整原始建筑，不将城市平地样例扩展成坡地接缝精度承诺。

基座采用同源 DEM 独立采样；地表基座与相对高度分开，屋顶保持局部等高。坡地基础向下延伸以减少接缝，但不声称还原实地基础。原始高度来源和统一垂直基准仍未知，不套 geoid 常数。有限范围、采样与预算造成的缺失必须反馈。

预算分两步：先读取全部候选瓦片，只保留各源分部的索引、边界、点数和三角面上界；再跨瓦片统一筛选，重新解码入选轮廓并采样 DEM。区域原始响应预算 40 MiB，缓存只保留未改写内部载荷的 building 层（最多 48 块 / 16 MiB），不驻留道路等其他层；缓存同时记录原响应大小，命中缓存也不能绕过区域原始响应上限。候选最多 100,000 个、扫描点最多 4,000,000 个，超出时明确失败，不伪装为完整扫描。当前普通轮廓入选上限 160,000 点，全场（含地标）300,000 面，原 80,000 点/120,000 面保留为历史对照。

选择以高度/足迹相对距离的角尺度排序，先为 2 km 外的合格远景预留最多 25% 预算，再补充 80 m 及以上高层至总预算 50%，随后按 500 m 近景格网轮流分配至总预算 70%，最后全局补充。所有排序用源瓦片/要素/分部索引稳定决胜，避免下载顺序决定结果。远景和高层预留未用完可供普通建筑使用。高度仍遵守源的 hide_3d 与分部属性，不硬编码地标。镜头方向和焦距不参与选择，避免拖动时频繁换网格。预算省略数量与实际读取瓦片数分别显示。

架空分部在 `render_min_height` 处保留不透明底面，底面与顶面均保留内院孔洞；地面建筑的下裙不增加埋地底面三角形。这里不模拟建筑内部、窗户透光或独立结构杆件。

图层先于星空、日月与天气天空合成，不访问 SDK 私有纹理或字段，绘制后恢复 GL 状态。视角与镜头只更新相机 uniform，光照只更新材质 uniform。建筑开始加载、替换、关闭与失败均清空旧标注遮挡；加载稳定后重新查询，纯转向继续沿用方向遮挡缓存。关闭/卸载取消请求、清理 GPU 资源；迟到响应不覆盖新机位。

轮廓只去除相邻重复点与严格共线且不反向的中间点，保持闭环、孔洞及轮廓面积，不使用容差、外接盒或随机补充。保留非共线小台阶与高度，清理后的点数和三角面上界参与同一次预算选择；渲染阶段执行相同清理以避免成本不一致。该项不是有损屏幕 LOD，真实数据的精简比例有限。当前样例、网络与画面边界见[远景验收](../plan/building-distance.md)。

## 精选地标模型

单体独立按约 50 km 范围读取；距离以地面锚点 WGS84 三维弦长判断，避免只计算水平 ENU 时误纳入地球背面。普通窗口可能与塔身相交（锚点距机位不超过 5 km 加目标水平边界）时，仍在整块源瓦片上按目标已登记的源分部 ID、相对高度及邻近位置确认，再过滤入选粗体块。确认在五公里候选过滤之前完成，避免只有部分分部入选时出现边界断层。窗口外使用已有注册的同源模型和地标锚点 DEM，不额外扫描远处城市瓦片；该距离没有对应粗体块，模型失败不能声称已回退。

已接入地标按自动生成目录分别读取，逐项保存应用/回退状态；距离决定加载顺序，转向和焦距不参与请求身份。资源先完成大小、SHA-256、格式、坐标、法线和索引检查，再读取同源 DEM 作为地面基座；近处失败保留原粗体块，不删除邻楼。尚未确认分部关系时不猜测替换范围。资源是固定内容的 TTLM 1，包含本地 ENU float32 位置/法线与 uint32 索引；没有纹理、运行时 glTF 解码或新引擎。压缩输入最多 2 MiB、解压最多 4 MiB，模型缓存按 ID 和内容哈希隔离，最多 16 份/8 MiB 几何字节，按最近使用淘汰；清理期间的迟到请求不能重新驻留。关闭清理 GPU、重试清空缓存。仍随本次建筑请求统一提交几何；普通区域请求失败会使整个建筑图层失败，不把地标单独声明为就绪。

网格使用锚点 ENU，经 WGS84 切平面基向量转换到当前观察者 ENU，随后共用摄影矩阵与 DEM 对数深度。法线应用同一旋转，索引绑定到独立 VAO；地标不做地图瓦片边缘裁切。纯转向/调焦只更新 uniform。按距离逐项扣除成功地标的实际面数（由生成目录记录，各目标独立核对），失败项不扣除并保留对应粗体块，其余普通建筑继续按统一选择规则分配，总面数不超过 300,000；普通轮廓点上限 160,000 与地标顶点上限 128,000 分别约束输入，不能混称全场 GPU 顶点上限。当前使用同一地标几何，不按焦距或转向切换 LOD；远景雾、曲率及深度仍使用原模型，未新增几何折射。

远景地表衔接修正为既有地形兼容补丁增加覆盖范围支持：当建筑开启且已接入地标在 5–50 km 内时，应用在公开 Source 的 LOD 回调上附带自有范围标记。固定 SDK 的 coveringTiles 仅为带标记的地形/DEM 遍历克隆变换，把覆盖远裁剪下限扩至 75 km；真实相机、摄影矩阵、深度与雾矩阵不变。应用不读取 Map.transform 等未在发布 Map API 中暴露的字段。普通地图及无标记回调保持原行为，关闭或离开范围后移除扩展。建筑图层本身仍不修改 SDK。

单体的源处理和近似注册见[晴空塔首步](../plan/skytree-landmark.md)，距离/预算历史见[地标远景](../plan/landmark-distance.md)，覆盖修正与接地验收见[地表校准](../plan/landmark-ground-calibration.md)。本轮扩展见[东京塔与上海中心](../plan/landmark-expansion.md)，使用固定目录与同一 TTLM 格式，不增加插件系统。

地标来源、转换和运行时目录改由[批量制作流程](landmark-pipeline.md)维护。单资源顶点门槛由 80,000 调为 128,000 以保留东京塔硬边，压缩/解压/面数限制不变；当前 LRU 条目最多 16 项，几何字节仍限 8 MiB。东京塔真实画面本轮按用户要求暂缓，未沿用其他模型验收状态。
