# 摄影预览的 WGS84 / ENU 投影

更新：2026-11-05。默认预览实际网格采用以下几何，地图浏览仍使用原有 Mercator。高度基准限制见[高度决策](elevation-datum.md)，执行结果见[验收记录](../plan/terrain-perspective.md)。

## 一致的方向与深度

预览保留 MapLibre 的 DEM、LOD、地表和水体颜色、阴影及资源生命周期。在实际地形顶点的最后投影阶段，先把经纬度和高程转换为 WGS84 曲面上的位置，再转到实际眼点的东、北、天坐标（ENU），最后按真实相机方位、俯仰和传感器视场投影。水体颜色贴在相同网格上，随同曲面移动；未改变水位模型。

实际眼点仍从公开 `CustomRenderMethodInput.modelViewProjectionMatrix` 反算，角度从公开 Map API 读取。在 `prerender` 阶段更新坐标桥接，使本帧地形使用避让后的实际姿态；用户计划独立保留。日月继续按同一实际姿态的 `projectDirection` 投影，天空圆盘深度为 1；修正后的地形使用完整 0—1 主深度范围，有限距离位于天空之前。GPU 遮挡查询继续作用于真实绘制缓冲，不读取 SDK 私有纹理。

地图定向也采用共用 `src/domain/geodesy.ts` 的椭球 ENU 水平方位，不再使用球面方位或截断到 0.1°。地图点没有高程输入，因此只取参考椭球零高点的水平角，不自动推定俯仰或承诺对准某个山脊最高像素。扇形和方向把手的半径仍为缩放示意，生成目的点时迭代修正其 ENU 方位，保持与相机角度一致，不将示意半径解释为真实测地距离。

主地形片元深度使用 `log2(1+d) / log2(10000001)`，d 为沿实际相机前方的距离，结果限制在 1 之前。低近裁剪下，普通无限远深度会将 15 km 处相差 1 m 的表面量化到同一浮点值；对数深度保留远山前后顺序。顶点和片元显式使用相同的 highp uniform/varying 精度，避免宿主默认精度不同导致链接失败。CPU 对数深度函数及共享 GLSL 分别位于 `terrain-perspective-math.ts`、`terrain-depth.glsl`。

## 数值稳定性

直接在单精度 GPU 上计算 ECEF 再减去地球半径，会把微小误差放大到长焦像素。实现拆成两步：

1. CPU 双精度计算每个瓦片中心零高度点相对眼点的 ENU，以及瓦片局部基底到眼点基底的旋转。
2. GPU 计算顶点相对瓦片中心的位移，加入高程，再应用上述平移、旋转和摄影相机矩阵。

`terrain-perspective-math.ts` 提供 CPU 瓦片参考与相机矩阵，`terrain-projection.glsl` 提供实际顶点核。核使用稳定的 Mercator 纬差、半角差及曲率半径差公式，避免接近大数相减；小角度正弦使用局部多项式。真实 Chrome 曾在原生三角函数路径量到约 0.49 CSS px 的参考点残差，改用局部多项式后降至约 0.00053 px；这属于绘制数值验证，不是实景精度。

瓦片中心数据按眼点缓存，最多 256 项；只改变角度、镜头或时间不重新下载 DEM。相机矩阵使用传感器与画幅的水平/垂直视场，近裁剪取离地高度的四分之一、限制在 0.005—1 m，远平面使用无限远投影。网格、纹理与瓦片缓存上限沿用既有策略，没有增加区域数据下载。

## 固定 SDK 的本地桥接

上游没有在当前摄影机位下提供所需的任意椭球地形投影接口。本项目固定 SDK 6.16.0，在安装时由 `patch-terrain-perspective.mjs` 和 `patch-terrain-depth.mjs` 扩展本地构建：

- 修正实际使用的 ESM、原始 GLSL、生成 GLSL 模块和源码绘制路径；核对版本和唯一签名，重复执行幂等，签名不匹配即失败。
- 在实际地形颜色/主深度绘制前，通过 `Symbol.for("tamatamatori.terrain-enu.v1")` 调用当前 WebGL 上下文上由本项目安装的函数。参数仅包含 GL、program 和瓦片标识；应用代码不访问 SDK 私有字段。
- `TerrainPerspective` 自定义图层安装/卸载该函数，上传瓦片与相机 uniform。未安装桥接的上下文使用原来的着色器分支和深度范围，普通地图不启用修正。
- SDK 自身用于平面瓦片管理的辅助深度/高度纹理及 CPU 覆盖逻辑保留原语义。正式山体、水体和日月使用修正后的主绘制深度。上游 `map.project()` 和原始 MVP 继续作为旧平面参考，不能用来直接定位新增地面对象。

这是本地扩展契约，**不是上游公开 API**。原有 LOD 补丁仍由同一 postinstall 入口执行；升级 SDK 必须同时验证 LOD、ENU 和对数深度补丁。版权、修改声明与 BSD 许可随应用提供。失去桥接或着色器不可用时明确显示错误，不将平面降级静默冒充修正成功。

Vite 预编译缓存目录包含三个安装补丁及两个共享 GLSL 文件的签名，避免 SDK 包版本未变时仍复用平面或旧着色器缓存。更新内核后执行安装脚本并重新启动开发服务，缓存自动隔离。

## 校准与后续图层边界

开发校准器使用与实际网格相同的 GLSL 和 renderer uniform，通过 WebGL2 transform feedback 读取固定点的射线与屏幕坐标，并对照独立 ECEF/ENU。探针仅由开发校准页触发，退出时释放 program、buffer、VAO 和 transform feedback；捕获前后恢复 GL 状态。正常页面没有参考点、数值面板或 GPU 读回。

后续银河、深空天体等无限远目标可以复用 `projectDirection` 的 ENU 方向、实际相机姿态和天空深度，再接受相同地形遮挡。有限距离对象应使用相同 ENU、`photoCameraMatrix` 和对数片元深度，不能混用 MapLibre 平面矩阵或普通透视深度；空间站位置及高度基准在对应阶段验证。不提前创建未来图层或通用框架。

几何一致不消除源 DEM 分辨率、三角网插值、未知垂直基准、参考点坐标舍入、地面大气折射、建筑植被或未加载远地形的影响。天文图层仍沿用已有 0° 参考天文地平线及固定大气模型，地平线下可见性和海平线俯角不属于本轮精度承诺。`当前 DEM 未遮挡` 仍不是实地可见保证。
